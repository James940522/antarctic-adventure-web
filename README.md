# antarctic-adventure-web

**WHITE HORIZON / ANTARCTIC RUN**은 펭귄으로 남극 장애물을 피하며 거리와 SCORE 기록에 도전하는 의사 3D 전방 스크롤 게임이다. 메인 메뉴에서 클래식을 선택하면 자동 전진하고, 장애물에 닿으면 게임오버다.

## 실행

```bash
pnpm install
pnpm dev
```

기본 주소는 [localhost:3000](http://localhost:3000)이다. 3100 포트로 실행하려면 `pnpm dev --port 3100`을 사용한다.

## 링크 공유 미리보기

검색·공유 제목, 설명, 대표 주소는 `src/app/site-metadata.ts`에서 관리하고, `src/app/layout.tsx`에서 메타 태그와 Open Graph·X(트위터) 큰 이미지 카드에 적용한다. 공유 이미지는 사용자가 제공한 원본 `public/og.png`이며, `/og.png`로 제공한다.

배포 환경의 `SITE_URL`에 실제 공개 주소를 `https://`까지 포함해 설정하고 빌드한다. 이 주소를 대표 URL과 공유 이미지의 절대 주소에 사용한다. 값이 없으면 Vercel의 `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL` 순으로 사용하고, 로컬 개발에서는 `http://localhost:${PORT 또는 3000}`을 사용한다. 다른 호스팅 서비스에 배포할 때는 `SITE_URL`을 반드시 설정한다.

배포 후 페이지 소스의 `og:image`와 `twitter:image`가 공개 주소의 `/og.png`를 가리키고, 해당 이미지가 로그인 없이 열리는지 확인한다.

## 검색엔진 메타데이터

- 검색 제목·설명, canonical, robots/googlebot 태그는 서버에서 초기 HTML에 포함한다. 개발 환경과 Vercel Preview에서는 `noindex`를 지정하고, 프로덕션에서는 색인을 허용한다.
- `/robots.txt`는 페이지와 이미지 수집을 허용하고 `/api/` 수집은 제외한다. 색인이 허용된 환경에서는 `/sitemap.xml` 위치도 안내한다.
- `/sitemap.xml`에는 실제 공개 페이지인 홈(`/`)만 포함한다. 별도 URL이 없는 메뉴·랭킹 모달은 등록하지 않는다. 개발·미리보기 환경의 사이트맵은 비워 둔다.
- 홈에는 이름·설명·이미지·언어·브라우저 플랫폼·싱글플레이 정보를 담은 `VideoGame` JSON-LD를 포함한다. 실제로 수집하지 않은 평점이나 리뷰를 생성하지 않는다.
- Google Search Console 소유권 확인에는 `GOOGLE_SITE_VERIFICATION`, 네이버 서치어드바이저에는 `NAVER_SITE_VERIFICATION` 환경변수를 사용할 수 있다. 각 서비스가 발급한 메타 태그의 `content` 값만 설정하고 다시 빌드한다. 설정하지 않으면 확인 태그를 출력하지 않는다.

배포 후 실제 도메인의 대표 URL·`robots.txt`·`sitemap.xml`을 확인하고, 소유권 확인을 마친 검색엔진 도구에서 사이트맵을 제출한다. 메타 태그를 추가하는 것만으로 검색 등록이나 특정 순위를 보장하지 않는다. `keywords` 메타 태그는 Google 검색의 색인·순위에 사용되지 않으므로 추가하지 않는다. 기준: [Google 메타 태그 문서](https://developers.google.com/search/docs/crawling-indexing/special-tags), [Schema.org VideoGame](https://schema.org/VideoGame).

## 플레이

클래식을 선택하고 창이 활성 상태이면 14m/s로 자동 전진한다. 게임 화면을 클릭하거나 Tab으로 선택해 조작한다.

| 동작 | 키보드 | 표준 게임패드 |
| --- | --- | --- |
| 좌우 이동 | ← / → 또는 A / D | 왼쪽 스틱 X, D-pad 좌우 |
| 8m/s 가속 | ↑ 또는 W를 한 번 누르기 | 스틱 위로 기울리기, D-pad 위 |
| 8m/s 감속 | ↓ 또는 S를 한 번 누르기 | 스틱 아래로 기울리기, D-pad 아래 |
| 점프 | Space | 남쪽 버튼: Xbox A / PlayStation Cross |
| 게임오버 후 재시작 | 다시 도전 버튼 또는 새 Space 입력 | 새 남쪽 버튼 입력 |
| 일시정지 / 계속하기 | Escape 또는 HUD 버튼 | Menu / Start 버튼 |

- 속도 조절은 새 입력마다 8m/s씩 적용하며 상한이 없다. 키를 놓아도 선택 속도를 유지하고 14m/s 미만으로 감속하지 않는다. 누른 채로 반복 가감속하지 않으며 스틱은 중립으로 돌린 뒤 다시 기울인다.
- 좌우 이동은 연속적이다. 스틱 deadzone은 0.18이며 기울기에 비례해 이동한다. 변속은 정규화된 Y축 절댓값 0.5부터다.
- 펭귄은 뒷모습이며 화면 경계에서 몸과 날개까지 안에 남는다. 점프는 모든 속도에서 0.8초, 최대 높이 150을 유지하며 착지 전 0.12초 안의 새 점프 입력을 한 번 저장한다.
- 눈더미·보급 상자·빙설 바위·해빙 구멍·크레바스·잠자는 물개가 7개 레인에 등장한다. 처음 50m는 화면에 장애물이 없다. 배치·회피 규칙은 [장애물 계획](docs/OBSTACLE_ASSETS_PLAN.md)을 따른다.
- 랜드마크는 10km마다 등장한다. 도착하면 정확히 멈춰 2.5초간 축하한 뒤 같은 속도로 재출발한다.
- 충돌 순간의 거리와 평균 속도로 SCORE를 확정한다. 브라우저 최장 거리와 당시 평균은 자동 저장하고, 온라인 랭킹은 결과 화면에서 직접 저장한 판만 등록한다. 저장이 막혀도 게임을 계속 이용할 수 있다.
- 재시작 시 주행·점프·입력·장애물·아이템·랜드마크를 초기화하고 최고 기록은 유지한다.
- 게임 영역 밖으로 포커스가 이동하면 입력을 초기화하되 자동 전진은 계속된다. 다른 창·탭으로 이동하면 게임 전체를 일시정지하며 복귀 프레임의 긴 delta는 버린다.

키보드와 패드는 별도 전환 없이 함께 사용할 수 있다. 반대 디지털 방향은 상쇄되고 해당 축에서는 디지털 입력이 스틱보다 우선한다. 패드가 보이지 않으면 연결 후 버튼을 누른다. 비표준 패드는 축 0/1·버튼 0을 기본값으로 시도하며 API가 없거나 연결이 끊겨도 키보드는 동작한다.

## 모바일·태블릿

화면 폭 1024px 이하 또는 터치 중심 기기에서는 화면 하단 양끝에 반투명 조작 버튼을 겹쳐 표시한다. 왼손 영역은 점프·감속·왼쪽 이동, 오른손 영역은 가속·점프·오른쪽 이동을 제공한다. 여러 버튼을 동시에 사용할 수 있고 조작 버튼 위치는 게임 영역 폭과 독립적으로 기기 화면 양끝을 따른다.

화면의 긴 변이 짧은 변보다 **35% 이상 길고(비율 1.35 이상) 세로가 긴 경우에만** 게임과 버튼을 90도 회전한다. 예를 들어 390×844는 회전하고, 768×1024나 1024×1050은 그대로 표시한다. 이미 가로인 844×390도 회전하지 않는다. 기기의 OS 방향을 강제 잠그지 않으며 화면 크기가 바뀌어도 같은 게임 인스턴스와 기록을 유지한다.

손가락이 버튼 밖으로 움직여도 누른 상태를 유지하고, 손을 떼거나 터치가 취소되면 해당 입력을 해제한다. 탭 이탈·화면 회전·재시작에서도 입력이 남지 않는다. CSS가 안전 영역과 회전을 관리하고 모바일 게임 비율은 최대 21:9다. Phaser는 논리 폭 960을 유지하면서 화면 비율에 맞춰 높이를 바꾼다.

## 구현 상태와 구조

기존 실행 기반·통합 입력·플레이어 조작에 원근 코스, 거리 기반 장애물, 즉사 충돌, 기록·재시작을 연결해 거리 기록 모드의 한 판을 완성했다. 기존 시간제 스테이지와 피격 감속 규칙은 후속 별도 모드로 정리했다.

- `src/components/game/`: 메뉴·HUD·결과·입력 UI. `GameCanvas`는 React 화면과 DOM 마운트를 관리하고, `game-session.ts`는 Phaser 비동기 로딩·시간 초과·해제 대기와 명령 전달을 관리한다.
- `src/game/config/`: 해상도, 속도, 점프, 입력 등 튜닝 값
- `src/game/input/`: 키보드·게임패드·멀티터치 어댑터와 공통 입력
- `src/game/entities/`: Player 시뮬레이션과 뒷모습 PlayerView
- `src/game/systems/`: 원근, 무작위 생성, 연속 충돌, 주행 상태, 최고 기록, 코스 표시
- `src/game/systems/ranking-response.ts`: 랭킹 API 응답 검증. `RankingStore`는 요청·취소·재시도 상태를 관리하고 `RankingBoard`는 검증된 데이터만 표시한다.
- `src/game/scenes/`: 입력 → 시뮬레이션 → 표시·HUD 이벤트 연결
- `src/server/`: 기록 검증, 저장·순위 서비스, Supabase 접근. 서버 키는 `server-only` 경계에서만 사용한다.

Phaser 4 / Next.js App Router / React / TypeScript / Tailwind를 사용한다. 제공된 이미지·음원은 `public/asset/`에 두고 별도 상태 관리 라이브러리는 사용하지 않는다. 데스크톱 기본 논리 해상도는 960 × 540이며 월드 거리 10이 표시 거리 1m다.

메인 메뉴에서는 Phaser를 생성하지 않는다. 클래식 진입 시 동적으로 로드하며 게임 시뮬레이션은 Phaser가 소유하고 React는 최대 10Hz 스냅샷으로 HUD를 갱신한다. 개발 환경에서는 `?debugInput=1`과 `?debugObstacles=1`로 입력·판정을 확인할 수 있다.

## 검증

```bash
pnpm check          # 린트 → Next 타입 생성·타입 검사 → 테스트
pnpm qa             # check → Webpack 프로덕션 빌드
pnpm build          # 기본 Turbopack 프로덕션 빌드
pnpm build:webpack  # Webpack 빌드만 실행
```

Node.js 내장 테스트 러너로 입력·주행·충돌·재시작·저장·랭킹과 게임 생성/해제의 회귀를 검사한다. 최신 실행 결과와 실제 브라우저에서 확인한 범위는 [QA 점검 결과](docs/QA_REVIEW.md)에 기록한다.

현재 QA 실행 환경은 Turbopack의 PostCSS 보조 프로세스 포트 바인딩을 제한하므로 `pnpm qa`에서는 검증된 Webpack 빌드를 명시적으로 사용한다. 기본 `pnpm build` 동작은 유지하며 빌드 오류를 숨기거나 자동으로 다른 번들러를 재시도하지 않는다.

게임패드 자동 검증은 모의 스냅샷이다. 실제 Xbox·PlayStation·조이스틱 및 다른 브라우저의 하드웨어 검증은 남아 있다.
