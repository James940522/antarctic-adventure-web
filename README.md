# antarctic-adventure-web

펭귄으로 네온 박스를 피하며 가장 먼 거리에 도전하는 의사 3D 전방 스크롤 게임이다. 입력 없이 자동 전진하고, 박스에 닿으면 게임오버다.

## 실행

```bash
pnpm install
pnpm dev
```

기본 주소는 [localhost:3000](http://localhost:3000)이다. 3100 포트로 실행하려면 `pnpm dev --port 3100`을 사용한다.

## 링크 공유 미리보기

공유 제목·설명·Open Graph·X(트위터) 큰 이미지 카드는 `src/app/layout.tsx`에서 관리한다. 공유 이미지는 사용자가 제공한 원본 `public/og.png`이며, `/og.png`로 제공한다.

배포 환경의 `SITE_URL`에 실제 공개 주소를 `https://`까지 포함해 설정하고 빌드한다. 이 주소를 대표 URL과 공유 이미지의 절대 주소에 사용한다. 값이 없으면 Vercel의 `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL` 순으로 사용하고, 로컬 개발에서는 `http://localhost:${PORT 또는 3000}`을 사용한다. 다른 호스팅 서비스에 배포할 때는 `SITE_URL`을 반드시 설정한다.

배포 후 페이지 소스의 `og:image`와 `twitter:image`가 공개 주소의 `/og.png`를 가리키고, 해당 이미지가 로그인 없이 열리는지 확인한다.

## 플레이

페이지가 활성 상태이면 1단으로 자동 전진한다. 게임 화면을 클릭하거나 Tab으로 선택해 조작한다.

| 동작 | 키보드 | 표준 게임패드 |
| --- | --- | --- |
| 좌우 이동 | ← / → 또는 A / D | 왼쪽 스틱 X, D-pad 좌우 |
| 한 단 가속 | ↑ 또는 W를 한 번 누르기 | 스틱 위로 기울리기, D-pad 위 |
| 한 단 감속 | ↓ 또는 S를 한 번 누르기 | 스틱 아래로 기울리기, D-pad 아래 |
| 점프 | Space | 남쪽 버튼: Xbox A / PlayStation Cross |
| 게임오버 후 재시작 | 다시 도전 버튼 또는 새 Space 입력 | 새 남쪽 버튼 입력 |

- 속도는 **1·2·3단**, 각각 14·22·32m/s다. 키를 놓아도 현재 단수로 계속 달린다. 누른 채로 반복 변속하지 않으며 스틱은 중립으로 돌린 뒤 다시 기울인다.
- 좌우 이동은 연속적이다. 스틱 deadzone은 0.18이며 기울기에 비례해 이동한다. 변속은 정규화된 Y축 절댓값 0.5부터다.
- 펭귄은 뒷모습이며 화면 경계에서 몸과 날개까지 안에 남는다. 점프는 0.8초, 최대 100 논리 픽셀이고 박스 높이보다 충분히 높을 때 회피한다.
- 최초 박스 줄은 90m 앞에 있고 다음 줄은 32m 간격으로 온다. 120m마다 한 줄의 박스 수가 1개씩 늘어 최대 6개가 된다.
- 7개 후보 위치에 작은 무작위 편차를 주어 생성한다. 연속해서 이동 가능한 빈 통로를 남기며 최고 속도의 반응·이동 시간을 고려한다.
- 박스는 접촉 지점에서 72 × 72 논리 픽셀이다. 고정 네온색과 X 표시를 사용하고 흰 테두리만 4초 주기로 미세하게 밝아진다. 빠른 섬광·색상 점멸은 없으며 OS의 움직임 줄이기 설정에서는 테두리 효과도 끈다.
- 박스 접촉 순간의 거리를 확정하고 게임을 멈춘다. 완료한 주행의 최고 기록은 해당 브라우저/origin에 저장한다. 저장이 막혀도 현재 세션 기록은 유지한다.
- 재시작 시 위치·거리·속도·점프·입력·박스를 초기화하고 최고 기록만 유지한다.
- 게임 영역 밖으로 포커스가 이동하면 입력을 초기화하되 자동 전진은 계속된다. 다른 창·탭으로 이동하면 게임 전체를 일시정지하며 복귀 프레임의 긴 delta는 버린다.

키보드와 패드는 별도 전환 없이 함께 사용할 수 있다. 반대 디지털 방향은 상쇄되고 해당 축에서는 디지털 입력이 스틱보다 우선한다. 패드가 보이지 않으면 연결 후 버튼을 누른다. 비표준 패드는 축 0/1·버튼 0을 기본값으로 시도하며 API가 없거나 연결이 끊겨도 키보드는 동작한다.

## 모바일·태블릿

화면 폭 1024px 이하 또는 터치 중심 기기에서는 게임 아래에 반투명 조작 버튼을 표시한다. 왼쪽 끝의 ←, 오른쪽 끝의 →는 누르고 있는 동안 이동하고 가운데 점프 버튼은 한 번 눌렀을 때 한 번 점프한다. 이동과 점프를 두 손가락으로 동시에 사용할 수 있다. 작은 − / ＋ 버튼으로 한 단 감속·가속한다. 버튼은 캔버스 밖에 배치하며 배경 불투명도는 기본 22~28%, 눌렀을 때 40%다.

화면의 긴 변이 짧은 변보다 **35% 이상 길고(비율 1.35 이상) 세로가 긴 경우에만** 게임과 버튼을 90도 회전한다. 예를 들어 390×844는 회전하고, 768×1024나 1024×1050은 그대로 표시한다. 이미 가로인 844×390도 회전하지 않는다. 기기의 OS 방향을 강제 잠그지 않으며 화면 크기가 바뀌어도 같은 게임 인스턴스와 기록을 유지한다.

손가락이 버튼 밖으로 움직여도 누른 상태를 유지하고, 손을 떼거나 터치가 취소되면 해당 입력을 해제한다. 탭 이탈·화면 회전·재시작에서도 입력이 남지 않는다. CSS가 안전 영역 여백과 16:9 비율을 관리하며 Phaser는 고정 논리 해상도로 렌더링한다.

## 구현 상태와 구조

기존 실행 기반·통합 입력·플레이어 조작에 원근 코스, 거리 기반 장애물, 즉사 충돌, 기록·재시작을 연결해 거리 기록 모드의 한 판을 완성했다. 기존 시간제 스테이지와 피격 감속 규칙은 후속 별도 모드로 정리했다.

- `src/components/game/`: 브라우저 전용 Phaser 마운트, 10Hz 이하 HUD 스냅샷, 접근 가능한 결과·재시작 버튼
- `src/game/config/`: 해상도, 3단 속도, 점프, 난이도, 박스 튜닝
- `src/game/input/`: 키보드·게임패드·멀티터치 어댑터와 공통 입력
- `src/game/entities/`: Player 시뮬레이션과 뒷모습 PlayerView
- `src/game/systems/`: 원근, 무작위 생성, 연속 충돌, 주행 상태, 최고 기록, 코스 표시
- `src/game/scenes/`: 입력 → 시뮬레이션 → 표시·HUD 이벤트 연결

Phaser 4 / Next.js App Router / React / TypeScript / Tailwind를 사용한다. 외부 아트·폰트·음원과 추가 상태 라이브러리는 없다. 논리 해상도는 960 × 540이며 화면에 맞춰 16:9로 축소한다. 월드 거리 10이 표시 거리 1m다.

기본 화면은 플레이 HUD를 표시한다. `?debugInput=1`에서만 개발용 입력·플레이어 패널을 추가한다. 게임 시뮬레이션은 Phaser가 소유하며 React는 매 프레임 갱신하지 않는다.

## 검증

```bash
pnpm test
pnpm lint
pnpm exec next typegen
pnpm exec tsc --noEmit
pnpm build
```

Node.js 24 내장 테스트 러너를 사용한다. 입력·이동·원근·충돌·재시작·저장 실패를 검증하고, 무작위 코스 80개 × 100줄에서 최고 속도에 도달 가능한 회피 경로와 활성 오브젝트 수의 상한을 확인한다. 30·60·144 FPS의 이동·점프와 충돌 확정 거리도 검사한다.

터치 추가 후 자동 테스트 46개를 통과했다. 두 손가락 이동·점프, 마지막 손가락 해제, 짧은 탭, 입력 장치 병합, 캡처 해제·취소·회전·재시작 정리를 검사한다. 내장 브라우저에서 실제 화면 버튼의 이동·가속·점프와 390×844, 844×390, 768×1024, 1024×1050, 320×320, 1280×720 배치를 확인했다. 캔버스와 버튼이 겹치지 않고 논리 해상도와 캔버스 한 개가 유지된다. 실제 휴대폰·태블릿의 멀티터치는 추가 수동 검증 대상이다.

게임패드 자동 검증은 모의 스냅샷이다. 실제 Xbox·PlayStation·조이스틱 및 다른 브라우저의 하드웨어 검증은 남아 있다.
