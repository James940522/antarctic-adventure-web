# 거리 기록 모드 구현 계획

> 최신 장애물 구현은 [OBSTACLE_ASSETS_PLAN.md](./OBSTACLE_ASSETS_PLAN.md)를 따른다. 실제 PNG 6종·한 행 하나·35~55m(2칸 뒤 +10m)로 교체되었으며, 아래 다중 박스·거리별 밀도 증가는 이전 계획이다. CourseSegmentSystem은 아직 구현하지 않았다.

사용자 요청에 따라 기존 4~6단계의 원근·충돌·한 판 흐름을 거리 기록 모드로 먼저 완성한다. 구현 순서는 다음과 같다.

1. **자동 전진과 상한 없는 속도**: 기본 14m/s로 자동 주행, ↑/↓를 새로 누르면 8m/s씩 변경. 하한 14m/s, 가속 상한 없음. 좌우 이동·점프·화면 경계 유지.
2. **코스 원근**: 공통 PerspectiveSystem에서 플레이어·코스·박스의 거리와 위치·크기 연결. 실제 전진량만큼 배경과 박스 접근.
3. **박스 생성과 난이도**: 펭귄 크기의 네온 박스, 횡방향 무작위 배치, 거리별 동시 생성 수 1→6개. 같거나 이웃한 빈 통로를 예약하고, 고속에서 필요하면 감속해 회피 시간을 확보. 빠른 섬광 없이 고정 네온색과 느린 테두리 밝기 변화 사용. 움직임 줄이기 설정에서는 밝기 변화 생략.
4. **충돌과 기록**: 거리·횡좌표·점프 높이의 연속 충돌 검사, 접촉 즉시 게임오버와 거리·평균 속도 확정. 최고 거리와 당시 평균 속도를 해당 브라우저에 함께 저장하며 저장 불가 시 메모리 기록 유지.
5. **한 판 완성**: 거리·최고 기록·속도(m/s)·난이도 HUD, 게임오버·재시작, 창/탭 이탈 일시정지, 입력과 장애물 완전 초기화.
6. **검증과 원래 계획 정합성**: 생성 통로·충돌·속도·재시작·저장 실패를 자동 검증하고 실제 브라우저 확인. AGENTS와 순차 계획에서 즉사 규칙과 거리 점수를 우선하도록 수정. 기존 시간제 스테이지·피격 감속은 이 모드와 섞지 않고 후속 별도 모드로 보존.

거리 단위: 월드 거리 10 = 표시 거리 1m. 속도는 14m/s에서 시작해 22/30/38/46…m/s로 계속 높일 수 있다. 최초 박스 줄은 90m 앞, 다음 줄 간격은 32m다. 120m마다 한 줄의 박스 수가 하나 늘고 최대 6개다. 7개 후보 위치 중 한 통로는 항상 비우며, 다음 통로는 이전 통로와 같거나 바로 이웃한다.

후속 랜드마크 도착 규칙: 10km 간격(첫 10km, 최종 100km)의 목적지가 정면에서 300~700m에 걸쳐 커진다. 각 접근 시작 20m 전부터 목적지 160m 뒤까지 장애물 줄을 생성하지 않는다. 도착 거리에서 멈춰 2.5초간 펭귄이 뒤돌아 기뻐하고, 랜드마크가 사라진 뒤 선택 속도로 재출발한다. 축하 중에는 거리·주행 시간이 증가하지 않고 입력을 주행에 반영하지 않으며, 창 이탈 때 축하 시간도 멈춘다. 같은 시점의 충돌은 게임오버가 우선하고, 다시 도전은 여전히 0m부터다.

완료 조건: 입력 없이 자동 전진 → 조작으로 속도 변경·회피 → 박스 접촉 시 기록 확정 → 다시 도전이 동작하며, 기존 실행 기반과 입력·뒷모습·점프·경계 제한을 유지한다. 실제 게임패드 하드웨어 검증 여부는 별도로 기록한다.

## 최초 거리 기록 모드 구현·검증 이력

아래는 3단 속도를 사용하던 최초 구현의 기록이다. 현재 속도·터치 배치는 아래 후속 변경이 우선한다.

1~6번을 구현했다. 기존 4단계 원근, 5단계 장애물, 6단계 한 판 흐름을 이 모드에 통합해 완료했다. 입력·뒷모습·좌우 경계·점프는 유지하고, 연속 가감속은 3단 속도로, 일반 충돌 감속은 즉사로 변경했다. 원래 시간제 목적지 스테이지는 후속 별도 모드로 문서화했다.

- 자동 테스트 **37개** 통과: 입력과 속도 탭·held 처리, 30·60·144 FPS, 원근, 점프 회피·연속 충돌, 게임오버의 거리 확정·중복 종료 방지, 재시작, 저장 실패.
- 무작위 코스 **80개 × 100줄**에서 최고 속도의 반응·횡이동 시간을 포함한 도달 가능한 빈 통로, 박스 간격, 활성 오브젝트 상한을 검사했다.
- 내장 브라우저에서 입력 없이 전진, 2·3단 전환, 거리·난이도 변화, 네온 박스 접근, 접촉 게임오버, 재시작, 새로고침 후 최고 기록 보존을 확인했다.
- 1280 × 720과 390 × 844에서 표시를 확인했다. 작은 화면 결과창과 버튼의 경계를 DOM으로 확인했고 캔버스는 하나였다. 런타임 오류 로그는 없었다.
- 린트·타입 검사·프로덕션 빌드 통과. 실제 Xbox·PlayStation·일반 조이스틱과 다른 브라우저 하드웨어 검증은 미완료다.

## 후속 변경 — 속도 상한 제거와 양손 터치 조작

- `selectedSpeed`를 14m/s부터 8m/s씩 올리고 내린다. 가속 상한 없이 선택 속도를 유지하며, 감속은 기본 속도까지만 가능하다. 랜드마크에서는 실제 속도 0을 표시하고 2.5초 후 선택 속도로 재출발한다.
- 왼쪽에 `점프 · ↑ · ↓`, 오른쪽에 `↓ · ↑ · 점프`를 대칭으로, 각 묶음 아래에 큰 좌/우 이동 버튼을 배치했다. 반투명 배경과 화면 비율에 따른 회전을 유지하며 버튼은 최소 44px이다. 후속 화면 확대 작업으로 패드를 게임 폭과 독립적인 기기 화면 하단 좌우 끝에 고정했다. 패드는 게임 또는 여백 위에 겹쳐질 수 있으며 가장 앞에 표시한다.
- 무한 가속으로 줄 사이 반응 시간은 줄어들 수 있다. 빈 통로 배치는 유지하며, 플레이어가 감속으로 회피 시간을 확보한다. 고속에서도 이번 프레임 이동 끝까지 먼저 생성하고 충돌 후 지나간 박스를 회수해 관통을 막는다.
- 자동 테스트 58개 통과: 1,002회 가속과 감속 하한, 양손 중복 입력, 30/60/144 FPS의 고속 충돌, 랜드마크 정지와 선택 속도 복원을 포함한다.
- 내장 브라우저에서 양손 버튼으로 62m/s까지 가속, 14m/s로 감속, 양쪽 점프와 키보드 가속을 확인했다. 844×390, 회전된 390×844, 회전하지 않은 320×360, 데스크톱 1280×800을 확인했다. 당시 작은 화면에서도 버튼이 게임 영역 아래에 들어가며 캔버스는 하나였다. 최신 배치는 아래 화면 확대 규칙이 우선한다.
- 린트·타입 검사와 `pnpm build --webpack` 통과. 기본 Turbopack 빌드는 실행 환경의 CSS 처리용 로컬 포트 생성 제한으로 완료하지 못했다. 최종 새로고침에서 새 런타임 오류는 없었다. 실제 모바일 기기와 게임패드 하드웨어 검증은 별도다.

## 후속 변경 — 모바일 화면 확대와 점프 터치 영역

- 모바일 게임은 버튼용 하단 공간 없이 화면 높이를 채우며, 가로/세로 비율은 최대 21:9로 제한한다. 초광폭 화면에서는 게임을 중앙에 두고 남는 폭을 양옆 여백으로 남긴다.
- 패드는 게임 폭과 독립적으로 화면 좌우 끝의 안전 여백에 고정한다. 게임·여백 위에 반투명으로 겹치고 HUD보다 앞에 표시하며, 버튼 이외의 영역은 입력을 통과시킨다.
- 양쪽 점프 버튼 높이를 72px로 늘리고 가감속보다 넓은 열을 배정했다. 844×390 화면에서는 약 92×72px이다. 버튼 내부 글자는 포인터를 가로채지 않고 버튼이 직접 입력을 받는다. 밝은 설원과 어두운 여백 모두에서 글자가 보이도록 그림자를 적용했다.
- 코스의 논리 폭 960과 충돌 좌표는 유지하며, Phaser 렌더링 높이·지평선·플레이어 접촉 위치를 실제 게임 영역에 맞춘다. 크기 변경 시 게임 인스턴스와 주행 상태는 유지하고 입력만 초기화한다. 낮은 화면에서 랜드마크가 HUD를 가리지 않도록 이미지 높이도 제한한다.
- 자동 테스트 62개 통과: 짧은 pointer 탭과 이동 동시 점프, 화면 비율별 투영·충돌 좌표 유지, 랜드마크 표시 경계를 포함한다. 린트·타입 검사·`pnpm build --webpack` 통과.
- 내장 브라우저에서 844×390 전체 화면과 점프 버튼 가장자리 입력, 1000×300에서 중앙 700×300 게임 및 화면 양끝 패드, 320×360에서 버튼 간격, 390×844 회전 배치, 1280×800에서 기존 960×540 데스크톱 화면을 확인했다. 캔버스는 하나이며 새로고침 후 브라우저 오류는 없었다. 실제 모바일 터치 하드웨어 검증은 별도다.

## 후속 변경 — 평균 속도와 거리 기록

- 주행 중 평균 속도를 HUD에 표시하고, 게임오버 결과는 `평균 36.5 m/s로 248 m 전진`처럼 거리와 함께 표시한다. 평균은 반올림 전 거리 / 실제 주행 시간으로 계산하며 랜드마크 축하·창 이탈 시간은 제외한다. 고속 충돌 프레임도 접촉 시점까지의 시간만 반영한다.
- 최고 기록은 거리로 비교하며, 갱신 시 해당 주행의 평균 속도를 같이 저장한다. 더 짧거나 같은 거리에서 더 빠르게 달렸더라도 기존 최고 기록 쌍을 덮어쓰지 않는다. 기존 거리 전용 기록은 `평균 미측정`으로 유지하고 다음 갱신부터 새 형식으로 저장한다.
- 자동 테스트 65개 통과. 가감속 시간 비중, 30/60/144 FPS와 접촉 시점 평균, 랜드마크 정지 제외, 재시작, 기존 기록 호환, 손상 데이터·저장 실패를 확인했다. 린트·타입 검사·`pnpm build --webpack` 통과.
- 내장 브라우저에서 가속에 따른 현재/평균 속도 차이와 게임오버 결과를 확인했다. 844×390 및 1000×300에서 결과와 재시작 버튼이 표시되고 조작 가능하다.

## 후속 검증 — 기록 보호와 모바일 버튼 간소화

- 모바일 윗줄을 왼쪽 `점프 · 속도 ↓`, 오른쪽 `속도 ↑ · 점프`로 줄였다. 아래 좌우 방향키는 유지해 총 6개 버튼이며, 남는 폭을 점프 터치 영역에 배정한다. 점프는 높이 72px, 844×390에서 폭 약 131px, 320×360에서 약 85px다. 기존 대칭 8개 버튼 배치보다 이 규칙이 우선한다.
- 이미 열린 다른 탭의 최고 기록을 이전 기록으로 덮어쓰는 상황을 재현했다. 저장 직전에 최신 기록을 다시 읽고 거리·평균 쌍을 보존하며, 결과 화면도 해당 기록과 신기록 여부를 반영한다. localStorage 읽기·쓰기는 트랜잭션이 아니므로 서로 다른 탭의 정확히 동시인 쓰기를 원자적으로 보장하지는 않는다.
- Fast Refresh에서 평균 추적 이전의 스냅샷이 잠시 남아도 평균 표시의 `toFixed` 호출로 화면이 중단되지 않게 했다.
- 테스트 66개, 린트·타입 검사, Webpack 프로덕션 빌드를 통과했다. 프로덕션 서버에서 좌측 감속·우측 가속, 점프, 결과, 최고 거리·평균 속도의 새로고침 후 복원을 확인했고 브라우저 오류는 없었다. 320×360과 회전된 390×844에서도 버튼 6개가 화면 안에 있고 캔버스는 하나였다.
- 기본 Turbopack 빌드는 권한을 확대한 재시도에서도 PostCSS 내부 포트 생성 단계의 `EPERM`으로 중단됐다. 코드 컴파일·프로덕션 실행은 `pnpm build --webpack`으로 검증했다. 실제 휴대폰의 멀티터치 및 게임패드 하드웨어 검증은 별도다.
