# 현재 구현 점검 결과

## 2026-09-24 최종 빌드·QA

속도 조절·원근 보정과 현재 작업 트리 전체를 대상으로 `pnpm qa`를 다시 실행했다. **172개 테스트, ESLint, 타입 생성·TypeScript 검사, Webpack 프로덕션 빌드 모두 통과**했다. `pnpm start --hostname 127.0.0.1 --port 3102`로 해당 빌드를 실행해 내장 브라우저에서 확인했다. 이번 점검에서 추가로 수정할 게임 오류는 발견되지 않았다.

실물 모바일 멀티터치·게임패드·BGM 청취·다른 브라우저 엔진은 직접 검증하지 않았다. 입력 병합·장치 초기화·랜드마크·아이템·충돌·점수·기록 저장의 세부 회귀는 자동 테스트로 검증했다. 아래 내용은 2026-09-23의 이전 점검 기록이다.

## 범위와 환경

2026-09-23 현재 작업 트리에서 빌드·린트·타입·기존 테스트와 프로덕션 브라우저 동작을 점검한 뒤, QA 후속 개선과 코드 구조 점검을 수행했다. 환경은 macOS arm64, Node.js 25.2.0, pnpm 12.3.4, Next.js 16.3.5다. 정상 플레이 점검에 이어 게임 초기화 실패·취소와 잘못된 랭킹 응답 경로를 보완했다. 별도 작업의 장애물 배치·SEO·점프 입력 비활성화·시간에 따른 기본 속도 증가 변경은 보존했으며, 최종 자동 검사에는 해당 변경도 포함됐다.

커밋 준비 시에는 QA 개선 파일만 스테이징하고 해당 내용을 별도 임시 폴더로 추출해 `pnpm qa`를 다시 실행했다. 이 독립된 커밋 범위는 테스트 **152개**, 린트·타입 검사·Webpack 빌드를 모두 통과했다. 위 154개 결과는 별도 작업의 장애물 배치와 자동 가속까지 포함한 작업 트리 점검 기록이며, 해당 변경과 신규 이미지는 이번 QA 커밋에 포함하지 않았다. 점프 입력 임시 비활성화는 이후 별도 작업에서 되돌려져 커밋 시점에는 키보드·패드·터치 점프가 활성 상태다.

기본 빌드는 `globals.css`의 PostCSS 처리 중 보조 프로세스가 포트를 열 때 `Operation not permitted (os error 1)`로 실패했다. 권한을 확장한 실행에서도 동일하게 재현됐다. CSS 문법이나 TypeScript 오류는 보고되지 않았고, 동일 소스의 Webpack 빌드는 성공했다. 현재 실행 환경의 포트 권한 제한으로 분류하며, 실제 배포 환경에서 Turbopack 빌드가 성공하거나 실패한다고 단정하지 않는다.

현재 검증 환경에서 사용할 수 있는 명령은 다음과 같다. 로컬 서버 실행에는 포트 바인딩을 허용하는 환경이 필요하다.

```bash
pnpm qa
pnpm start
```

최종 빌드의 라우트는 정적 `/`, `/_not-found`, `/icon.png`, `/robots.txt`, `/sitemap.xml`과 동적 `/api/rankings`, `/api/records`다. 기존 3100 포트의 서버는 종료하지 않고 별도 3217 포트에서 검증했다.

## 후속 수정과 구조 정리

- **게임 초기화:** 기존 15초 제한은 동적 import와 이전 게임 해제 이후부터 시작해 다운로드·해제 대기가 끝나지 않으면 로딩 화면에 남았다. 제한을 로딩 시작부터 적용하고 실패 후 늦게 도착한 모듈·콜백이 게임을 다시 만들거나 UI를 갱신하지 않도록 했다. 로딩 중 메인 메뉴로 돌아가는 버튼도 추가했다.
- **오류 후 정리:** 생성 함수가 반환하기 전에 오류를 알리는 경우에도 반환된 게임을 해제한다. 오류·재시도 시 이전 HUD·일시정지 스냅샷을 비워 새 게임에 남지 않게 했다.
- **랭킹 응답:** 배열 여부만 검사하던 응답 검증을 별도 파서로 분리했다. 상위 목록과 본인 기록의 UUID·이름·숫자 필드를 확인하고 오류 상태에서 재시도할 수 있게 했다. 시간 초과는 즉시 오류 상태로 바꾸고 늦은 응답을 무시하며, 화면을 닫을 때 요청과 타이머를 정리한다.
- **QA 명령:** `typecheck`, `check`, `build:webpack`, `qa` 스크립트를 추가했다. `pnpm qa`는 현재 환경에서 통과하는 Webpack을 명시적으로 사용하며 기본 `pnpm build`는 유지한다.
- **문서:** README의 이전 3단 속도·네온 박스·게임 아래 터치 패드 설명을 현재 동작과 일치시키고 검증 명령과 책임 경계를 정리했다.

## 기존 테스트로 확인한 항목

- 키보드·게임패드·터치 입력 병합, 버튼 edge와 deadzone, 입력 초기화.
- 모든 속도에서 0.8초인 점프, 착지 직전 입력 저장, 프레임 안의 착지·재점프 충돌 판정.
- 장애물 6종의 PNG 프레임·shuffle bag·점프 회피와 고속 연속 충돌. 별도 작업의 2→3→최대 4개 묶음 배치가 반영된 뒤, 앞뒤 간격·좌우 분포·30m/s에서 다음 묶음의 안전 레인까지 이동 가능한지 검사하는 테스트도 다시 통과했다.
- 랜드마크 10종의 거리·접근 안전 구간·정확한 도착·2.5초 축하·재출발.
- 거리·평균 속도·SCORE 계산, 최고 거리와 평균의 쌍 보존, 저장소 오류 처리.
- 아이템 수집 순서와 효과 만료, 일시정지·도착·게임오버·재시작 시 상태 처리.
- 오디오 설정과 재생 상태, 플레이어 ID·닉네임 저장, 수동 온라인 기록 저장과 랭킹 조회 상태.
- 서버 입력 검증·중복 저장·상충하는 기록 거부·순위 정렬·DB 실패 응답. DB 저장 검증은 테스트용 저장소로 수행했다.
- 게임 모듈 로딩 중 언마운트·시간 초과·늦은 완료, import 실패 후 재시도, 빠른 재진입 시 해제 이벤트 대기, 동기/비동기 부팅 실패, 해제 후 콜백·명령 차단 테스트 8개를 추가했다.
- 잘못된 상위/본인 랭킹 응답과 재시도, TOP 100 밖 본인 순위·0점 기록, 시간 초과 후 늦은 응답 무시 테스트 3개를 추가했다.

## 프로덕션 브라우저 확인

아래 주행 수치는 구조 개선 후 브라우저 점검 시점의 결과다. 이후 같은 작업 트리에 반영된 점프 입력 비활성화와 기본 속도 증가 변경은 최종 `pnpm qa`에 포함했으며, 이 문서의 브라우저 결과로 해당 기능의 수동 검증까지 주장하지 않는다.

- Chrome과 앱 내 브라우저에서 첫 방문 BGM 선택 → 닉네임 설정 → 메인 메뉴 → 클래식 로딩을 확인했다.
- Chrome에서 기본 14m/s 자동 전진과 충돌 게임오버를 확인했다. 해당 주행은 210m, 평균 14.0m/s, SCORE 210으로 표시됐다.
- 재도전 후 거리 초기화, 위 방향키 한 번으로 14→22m/s 가속, ESC 일시정지를 확인했다. 점프의 궤적·회피 판정은 위 자동 테스트 결과를 기준으로 한다.
- Chrome에서 메뉴 → 클래식 → 일시정지 → 메뉴를 3회 반복했다. 게임 캔버스는 1개, 메뉴에서는 0개였고 audio 요소는 1개였다. HUD 버튼과 ESC로 일시정지 창을 열 수 있었다.
- Chrome 새로고침 후 BGM 선택과 닉네임이 유지됐고 첫 방문 설정 창이 다시 나타나지 않았다.
- 앱 내 브라우저의 랭킹 보드가 실제 API에서 기존 순위를 불러왔고 테스트 플레이어는 미등록으로 표시됐다. 테스트 기록을 온라인 DB에 새로 저장하지 않았다.
- 확인한 구간의 브라우저 console error/warning은 없었다. 검증용 서버와 탭은 종료했다.
- 구조 변경 후 Chrome에서 로딩 중 메뉴 버튼 표시, 14→22m/s 가속, ESC/HUD 일시정지, 메뉴↔클래식 3회 반복을 다시 확인했다. 게임 캔버스 1개·메뉴 0개·audio 1개를 유지했고 실제 랭킹 응답도 정상 표시됐다. 이 재검증에서도 console error/warning은 없었다.

## 검증 한계

실물 모바일 기기의 멀티터치·화면 회전·노치, 실제 Xbox/PS 패드, Edge/Safari/Firefox는 이번 점검에서 직접 검증하지 않았다. 게임패드·터치 로직은 자동 테스트로 확인했다. 로딩 장애·해제 대기·잘못된 API 응답은 가짜 시계와 테스트용 모듈/응답으로 재현했다. BGM 실제 청취, 운영 DB에 대한 신규 기록 저장, 배포 환경의 기본 Turbopack 빌드는 검증하지 않았다. 앱 내 브라우저에서의 활성 창 제약을 피하기 위해 실제 주행·가속 검증은 Chrome에서 수행했다.
