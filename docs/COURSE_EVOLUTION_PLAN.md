# 랜드마크 이후 코스 확장 계획

상태: 작업 계획. 아래 구간·장애물 확장은 아직 구현하지 않았다.

최신 우선 작업으로 랜드마크 도착 연출을 구현했다. 속도 상한 제거에 맞춰 랜드마크를 10km 간격(첫 10km, 최종 100km)으로 늘렸고, 정면 접근·장애물 없는 구간·2.5초 축하 정지·자동 재출발을 지원한다. 아래 거리 구간 표는 여전히 별도 난이도 초안이며 랜드마크 이동에 따라 자동 변경하지 않는다. CourseSegment 구현 시 이 안전 구간 제외 규칙을 유지해야 한다.

목표는 같은 거리 기록 모드 안에서 멀리 갈수록 배치와 판단이 달라지는 코스를 만드는 것이다. 먼저 현재 박스로 구간 규칙을 검증하고, 실제 장애물과 행동을 하나씩 연결한다. HUD 개편과 별도 선택 난이도 UI는 이번 첫 작업의 범위에서 제외한다.

## 현재 코드에서 확인한 사실

- `Player`는 기본 14m/s에서 새 ↑/↓ 입력마다 8m/s씩 조절하며 가속 상한이 없다. HUD는 실제 m/s를 표시하고, 별도 선택 난이도 설정은 없다. 우측 난이도 숫자는 거리에서 계산한 한 줄의 최대 박스 수를 보여준다.
- `ObstacleSystem`은 7개 위치 중 최소 한 통로를 비우고, 다음 통로를 이전 통로 또는 이웃으로 예약한다. 줄 간격은 32m이고, 120m마다 개수가 증가해 600m부터 한 줄 최대 6개다.
- 장애물은 시간 간격으로 생성하지 않고 앞으로 보이는 월드 거리에 미리 배치한다. 따라서 구간 설정도 밀리초 타이머보다 미터 단위 줄 간격을 사용하는 편이 현재 구조와 맞는다.
- 누적 거리는 `Player`에 있고 `RunSystem`이 충돌 시 실제 접촉 위치, 랜드마크 도착 시 정확한 목적지 거리로 확정한다. 월드 거리 10 = 1m다. `LandmarkSystem`은 접근·도착·축하·퇴장 상태를 관리한다.
- 충돌은 현재 전부 즉사다. 종류별 충돌 폭·피격 감속·갇힘·탈출 상태는 아직 없다.
- `public/asset/`에는 랜드마크 10종만 있다. 얼음구멍·크레바스·물개 이미지와 애니메이션은 별도 준비가 필요하다.

## 구현 순서

| 순서 | 작업 | 체감 결과 | 난도 |
| --- | --- | --- | --- |
| 1 | 거리 구간 데이터와 박스 생성 연결 | 초반은 여유롭고 먼 구간일수록 배치가 까다로워짐 | 중 |
| 2-A | 장애물 공통 모델과 종료·피격 규칙 확정 | 서로 다른 장애물을 안정적으로 추가할 수 있음 | 중~높음 |
| 2-B | 얼음구멍 → 크레바스 → 물개 순으로 추가 | 점프·탈출·측면 회피를 선택하는 플레이 | 높음 |
| 3 | 물고기 → 깃발 → 보너스 점수 | 같은 거리에서도 플레이 결과가 달라짐 | 중 |
| 4 | 시각적 커브 → 완만한 횡방향 밀림 | 코스 방향에 따른 조작 변화 | 높음 |
| 5 | 설원 색·눈보라·사운드 | 구간 분위기와 행동 피드백 강화 | 후순위 |

각 단계는 실행 가능한 상태에서 검증하고 마무리한다. 다음 단계용 빈 시스템과 사용하지 않는 설정은 미리 추가하지 않는다.

## 1. CourseSegmentSystem과 실제 생성 연결 — 바로 다음 작업

### 구조와 책임

```text
Player의 누적 거리 → RunSystem의 확정 거리
                         ├─ LandmarkSystem: 접근·도착 연출
                         └─ CourseSegmentSystem: 현재 구간 조회

장애물을 배치할 예정 거리 → CourseSegmentSystem의 해당 구간 조회
                         └─ ObstacleSystem: 개수·간격·배치 선택
```

- `src/game/data/course-segments.ts`: 독립적인 구간 경계와 생성 설정.
- `src/game/systems/CourseSegmentSystem.ts`: 거리로 구간을 조회하고 다음 경계·진행도를 제공. Phaser에 의존하지 않는다.
- 구간 타입은 우선 데이터 파일에 함께 두고, 필요할 때만 별도 타입 파일로 분리한다.
- `RunSystem`에서 읽기 전용 미터 거리 접근점을 제공해 Landmark와 CourseSegment가 같은 값을 사용하게 한다. 별도 거리 누적기나 타이머는 추가하지 않는다.
- 두 시스템은 서로 import하거나 도착 이벤트로 난이도를 바꾸지 않는다. 각 경계는 독립적으로 수정할 수 있게 한다. 장애물 생성은 구간의 난이도를 선택한 뒤 랜드마크 안전 구간 배치를 제외한다.
- 현재 구간은 플레이어의 거리로, 앞으로 생성할 장애물은 **장애물의 배치 거리**로 결정한다. 120m 앞까지 미리 생성하는 현재 구조에서 경계 직후에 이전 구간 장애물이 뒤늦게 나오는 문제를 방지한다.
- 이미 생성된 장애물은 구간 전환 때 교체하거나 재배치하지 않는다. 재시작 시 생성 위치·예약 통로·구간 상태를 함께 초기화한다.

### 첫 구현의 설정

초기 밸런스는 의미가 명확한 실제 값으로 정의한다.

- `id`, `name`, `startDistance`, `endDistance`: 구간 식별과 미터 경계. 시작 포함·끝 제외, 마지막은 무한 구간.
- `minObstaclesPerRow`, `maxObstaclesPerRow`: 한 줄의 개수 범위. 실제 배치는 안전 통로 제약을 우선한다.
- `rowSpacingMeters`: 줄 간격. 생성 시 한 번만 월드 단위로 변환한다.
- `patterns`: 무작위 분산, 완만한 통로 이동, 통로 유지 후 전환 등 현재 박스로 구현할 수 있는 작은 패턴 목록.

`obstacleDensity`나 `spawnIntervalMultiplier`는 기존 600m 최대 난이도 공식에 중첩하지 않는다. 그 공식을 구간 설정으로 교체한다. 장애물 종류와 선택 난이도 보정은 해당 기능을 구현할 때 추가한다.

### 구간별 초기 튜닝안

아래 수치는 구현 후 기본·중간 속도(14~30m/s)와 더 높은 선택 속도에서 검증할 출발점이며 확정 밸런스가 아니다. 종류 도입 시점은 사용자 제안의 상세 표를 따라 크레바스 1.2km, 물개 3km로 잡는다.

| 거리 | 구간 | 첫 작업: 박스/줄 | 줄 간격 | 후속 장애물·패턴 방향 |
| --- | --- | --- | --- | --- |
| 0~300m | 출발 설원 | 1~2 | 44m | 적응, 여유 있는 통로 |
| 300~700m | 관측지대 | 1~2 | 42m | 얼음구멍 빈도 증가 |
| 700~1,200m | 펭귄 서식지 | 2~3 | 40m | 완만한 통로 이동 |
| 1,200~2,000m | 기상관측구역 | 2~3 | 38m | 크레바스 도입 |
| 2,000~3,000m | 빙하지대 | 2~4 | 36m | 얼음구멍·크레바스 혼합 |
| 3,000~4,000m | 보급로 | 3~4 | 34m | 물개 도입, 사전 예고 |
| 4,000~5,000m | 거대 빙산지대 | 3~5 | 32m | 종류별 혼합 비율 증가 |
| 5,000~6,500m | 통신구역 | 4~5 | 30m | 촘촘한 배치로 판단 간격 감소 |
| 6,500~8,000m | 미개척지역 | 4~6 | 28m | 통로 유지·전환 패턴 조합 |
| 8,000~10,000m | 대빙벽 | 5~6 | 26m | 상한 밀도, 연속 판단 |
| 10,000m+ | 심부 탐험 | 5~6 | 26m 이상 | 안전 상한 안에서 패턴 반복·변주 |

상한 없는 사용자 선택 속도 모델을 그대로 유지한다. 5km 이후의 속도감은 줄 간격과 패턴으로 만든다. 추후 속도 보정이 필요하면 실제 전진량에 한 번만 적용해 플레이어·장애물·랜드마크의 접근을 일치시킨다.

### 공정성

- 최소 한 칸이 비어 있다는 것만으로 충분하지 않다. 이전 줄의 통로에서 다음 줄의 통로까지 실제로 이동 가능해야 한다.
- 속도에 상한이 없으므로 모든 속도에서 동일한 반응 시간을 보장하지 않는다. 기본·중간 속도의 줄 간격 하한은 해당 속도, 횡이동 속도, 장애물 폭·깊이, 반응 여유와 프레임 지연 여유를 함께 계산한다. 표의 값이 이 조건을 어기면 간격을 넓히거나 통로 이동을 줄인다.
- 구간 경계를 넘는 두 줄도 같은 검사에 포함한다. 서로 인접하지 않은 먼 통로로 갑자기 이동시키지 않는다.
- 10km 이후에도 개수를 7개로 채우거나 간격·반응 시간을 무한히 줄이지 않는다. 숫자 상한을 유지하고 조합을 바꾼다.
- 선택 난이도를 나중에 추가하더라도 선택 속도와 별도 설정으로 둔다. 밀도에는 곱하고 간격에는 나누는 등 보정의 방향을 구분하며, 보정 후에도 같은 안전 제한을 적용한다.

### 첫 작업의 완료 기준

1. 0/300/700/1,200/.../10,000m 경계 바로 전·정확한 경계·직후에 올바른 구간을 선택한다.
2. 구간 데이터에 빈 구간·겹침이 없고 10km 이후에도 정상 조회한다.
3. 기존 증가 공식을 교체해 실제 박스 개수·간격·패턴이 바뀐다. 데이터 파일만 추가하고 끝내지 않는다.
4. 여러 무작위 시드와 모든 구간 경계에서 기본·중간 속도로 도달 가능한 연속 통로를 검증하고, 더 높은 속도에서는 감속·고속 연속 충돌을 확인한다.
5. 30/60/144 FPS, 일시정지·복귀, 충돌·재시작이 기존 규칙을 유지한다. 랜드마크 위치를 바꿔도 구간 결과는 바뀌지 않는다.
6. 기존 HUD 배치를 유지하고 난이도·한 줄 개수의 표시값만 실제 구간 설정에 맞게 연결한다. 자세한 구간 정보는 개발 디버그 표시를 활용한다.
7. 자동 테스트·린트·타입 검사·빌드·브라우저 확인을 수행한다.

## 2. 실제 장애물과 행동 — 공통 모델 후 한 종류씩

### 먼저 바꿀 구조

현재 `BoxObstacle`, `CourseView`, `CollisionSystem`은 박스의 동일한 크기와 높이를 가정한다. 다음 작업에서 공통 장애물 모델에 `type`, 위치, 종류별 충돌 폭·깊이·점프 회피 기준, 한 번 처리된 접촉 상태를 넣는다. 렌더링은 장애물 종류별 표현으로 분리하되 `PerspectiveSystem`을 공유한다.

이미지는 실제 파일을 확인한 뒤 로더에 등록한다. 얼음구멍은 지면에 눕힌 형태, 크레바스는 긴 틈, 물개는 등장 예고와 몸체가 구별되어야 한다. 물개에 필요한 애니메이션 프레임 수는 행동 프로토타입으로 먼저 결정한다.

### 종료 규칙: 행동 변경 전에 확정할 항목

새 요청의 감속·탈출 동작은 현재 즉사 규칙을 대체하는 방향이다. 그런데 모든 충돌을 회복 가능하게 만들면 기존의 게임오버·최고 기록 확정 시점이 사라진다.

권장 초안은 **한 판에 피격 3회면 게임오버**다. 최초 두 번은 종류별 감속·갇힘·탈출을 체험하게 하고, 같은 장애물의 중복 피격을 막는다. 크레바스는 빠질 때 한 번만 피격으로 세고 탈출을 추가 피격으로 세지 않는다. 이 값과 규칙은 아직 확정하지 않았으며 장애물 행동 작업 전에 결정한다. 종료 규칙을 추가하지 않으려면 즉사 거리 도전 규칙을 유지해야 한다.

회복 규칙을 도입할 때 필요한 피격 잔여 표시만 최소한으로 추가하고, 최고 기록은 규칙 버전별로 구분한다. 이전 즉사 모드의 기록을 삭제하거나 새 규칙의 기록과 무조건 비교하지 않는다. `AGENTS.md`의 즉사 우선 지침도 실제 행동 전환과 같은 작업에서 갱신한다.

### 구현 단위와 검증

1. **얼음구멍:** 점프로 회피, 접촉 시 짧은 휘청·일시 감속. 선택한 속도는 유지하고 회복 후 해당 속도로 돌아온다. 접촉 중 매 프레임 감속이 재시작되지 않아야 한다.
2. **크레바스:** 점프 실패 시 갇힘, 실제 전진 정지, 새로운 점프 입력으로 탈출. 이미 누르고 있던 점프로 자동 탈출하지 않는다. 갇힌 동안 코스·랜드마크 거리는 함께 정지하며, 탈출 직후 같은 틈에 재포획되지 않게 처리한다.
3. **물개:** 표시나 움직임으로 등장 예고 후 활성화, 접촉 시 더 큰 일시 감속. 예고부터 접촉까지 기본·중간 속도에서 회피 가능한 시간을 확보하고 고속에서는 감속을 활용하며 예약한 안전 통로를 갑자기 막지 않는다.

각 종류를 완성할 때 구간의 허용 종류·등장 비율과 연결한다. 두 종류가 섞인 상태의 충돌 우선순위, 점프 성공/실패, 중복 피격 방지, 재시작, 종료 경계를 검사한다. 종류별 크기·행동이 생긴 뒤에는 박스 기준 안전 통로 테스트도 함께 확장한다.

## 3. 아이템과 점수

- `ItemSystem`과 `ScoreSystem`을 분리하되 처음에는 물고기 한 종류의 생성·수집·삭제부터 완성한다.
- 깃발과 특수 깃발은 획득 점수·희소성으로 차이를 주고, 위험을 감수하는 수집 경로에도 회피 가능성을 남긴다.
- 거리 기록은 실제 전진 거리로 유지한다. 아이템 수집, 장애물의 성공적 점프 통과, 랜드마크 도착은 각각 한 번 발생하는 이벤트로 점수를 준다.
- 같은 장애물 위에서 점프를 반복하거나 정지해 중복 점수를 얻지 못하게 한다. 단순히 장애물 근처에서 점프했다고 성공 보너스를 주지 않는다.
- 최고 거리와 최고 점수를 별도 저장하고 재시작·저장 실패 처리를 검사한다. 실제 점수가 생기는 이 단계에서만 HUD에 점수 값을 추가한다.

## 4. 커브

- 먼저 거리별 곡률 데이터와 공통 코스 중심 오프셋을 만든다. 지면·표식·장애물·아이템·랜드마크가 같은 깊이에서 같은 중심을 사용하게 한다.
- 직선/좌/우 커브 전환을 부드럽게 만들고 시각적 커브만으로 원근·판정 일치를 검증한다.
- 그다음 약한 바깥쪽 밀림을 `Player`의 논리 횡좌표에 적용한다. 화면만 기울이거나 렌더링 좌표로 충돌을 검사하지 않는다.
- 횡방향 밀림을 포함해 안전 통로 도달 가능성을 다시 계산한다. 화면 끝 제한·점프·크레바스 탈출·모바일 회전도 함께 검증한다.

## 5. 날씨와 사운드

구간별 눈 색·먼 배경 변화부터 추가하고, 이후 얕은 눈발·눈보라·행동 효과음 순으로 진행한다. 시야가 줄어드는 날씨를 넣으면 최소 예고 시간을 유지하도록 생성 거리를 함께 검증한다. 움직임 줄이기 설정, 효과 밀도, 음소거와 오디오 시작 시점도 이 단계의 범위다.
