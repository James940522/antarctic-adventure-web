# 순차 구현 계획

현재 목표는 **키보드와 게임패드로 박스를 피하며 거리 기록을 세우고 다시 시작하는 MVP**다. 사용자 요청에 따라 4~6단계를 거리 기록 모드로 조정했다. 0~3단계 기록은 당시의 구현 이력이며 연속 가감속·포커스 정책은 아래 최신 규칙으로 대체한다. 각 단계는 바로 실행해서 확인할 수 있는 결과를 만든다. 기본 원칙과 상세 입력 계약은 [AGENTS.md](../AGENTS.md)를 따른다.

## 0. 보일러플레이트 정리 — 완료

- Next.js 안내 화면, 예제 링크, 기본 로고 SVG와 favicon 제거.
- Geist 폰트 로딩, 샘플 색상·다크 모드 스타일 제거.
- 한국어 문서 언어와 프로젝트 메타데이터 설정.
- App Router, Tailwind, TypeScript, ESLint, pnpm 설정 유지.
- 실행 방법과 구현 계획을 프로젝트 문서로 정리.

정리 직후 결과: 기본 안내 문구가 없는 빈 홈 화면. 이를 바탕으로 1단계 게임 화면을 연결했다.

## 1. Phaser 실행 기반 — 완료

**목표:** 브라우저에서 게임 화면이 안정적으로 생성되고 정리된다.

- `pnpm add phaser`로 게임 엔진 설치.
- `src/components/game/GameCanvas.tsx`를 만들고 홈 페이지에 연결.
- `src/game/config/game-config.ts`에 960 × 540 논리 해상도와 비율 유지 스케일 설정.
- `src/game/scenes/BootScene.ts`에서 초기화 후 `GameScene.ts`으로 전환.
- GameScene에 하늘·눈밭과 도형으로 만든 임시 플레이어 표시.
- Phaser와 scene 모듈의 브라우저 전용 로딩, 로딩·실패 표시, 언마운트 정리 구현.

완료 조건: 브라우저에 캔버스가 하나만 표시되고 창 크기를 바꿔도 비율이 유지된다. 재마운트·Fast Refresh에서 게임 루프와 캔버스가 중복되지 않으며 프로덕션 빌드가 통과한다.

이 단계에서는 메뉴, HUD, 장애물, 아트 에셋을 만들지 않는다. 실행 기반만 먼저 검증한다.

구현 결과: Phaser 4.2.1, 브라우저 전용 동적 import, BootScene → GameScene, 도형 기반 남극 배경과 임시 펭귄, 로딩·오류·재시도 화면을 추가했다. 기본 입력과 오디오는 아직 비활성화되어 있다. 임시 검증 페이지에서 일반 재렌더링 시 캔버스 유지, 언마운트 시 제거, 재마운트 및 초기화 실패 후 재시도 시 정상 복구를 확인했다. 검증 페이지와 오류 주입 코드는 제거했다.

브라우저 확인: Codex 내장 브라우저에서 1280 × 720, 390 × 844, 844 × 390 화면의 비율 유지와 화면 내 배치를 확인했다. 개발 중 Fast Refresh 후에도 활성 캔버스는 하나였다. 다른 브라우저와 실제 게임패드 검증은 입력 구현 이후 진행한다.

## 2. 키보드·게임패드 통합 입력 — 구현 완료, 실제 패드 검증 대기

**선행:** 1단계의 실행 가능한 scene.

- `src/game/input/input.types.ts`에 공통 입력 계약 정의.
- `KeyboardInput.ts`, `GamepadInput.ts`, `InputManager.ts` 구현.
- 방향키·Space, 스틱·D-pad·남쪽 액션 버튼 지원.
- 매 업데이트 게임패드 폴링, deadzone 0.18, 축 정규화, 장치 병합 적용.
- held·pressed·released 구분, 포커스 이탈 초기화, 연결·해제 처리.
- 임시 개발 표시로 정규화된 축과 점프 edge 확인.

완료 조건: 같은 행동이 두 장치에서 동일한 입력 값으로 전달된다. 게임패드가 연결된 상태에서도 키보드가 작동하고, 스틱 드리프트와 버튼 길게 누르기가 잘못된 이동·반복 점프를 만들지 않는다. 실제 컨트롤러를 사용하지 못했다면 하드웨어 검증은 미완료로 기록한다.

구현 결과: 공통 입력 계약, 방향키·WASD·Space 어댑터, 매 프레임 Gamepad API 폴링, deadzone, D-pad 병합, 점프 edge, 포커스 초기화, 리스너 정리를 추가했다. Phaser 입력 플러그인의 전역 키 캡처 대신 자체 어댑터를 사용한다. 입력 표시 패널은 개발 서버에서 기본 활성화하며 `debugInput=0/1` 쿼리로 끄고 켤 수 있다. React는 프레임별로 갱신하지 않는다.

검증 결과: 17개 자동 테스트에서 방향 충돌·deadzone·짧은 탭·장치 간 중복 점프 방지·연결 해제·API 부재·포커스 초기화·리스너 해제를 확인했다. 내장 브라우저에서는 클릭·Tab 포커스, Space 눌림·해제 횟수, 게임 밖 입력 비활성화를 확인했다. 연결된 실제 컨트롤러가 없어 Xbox·PlayStation·일반 조이스틱 하드웨어 검증과 브라우저 교차 검증은 미완료다.

## 3. 플레이어 이동과 점프 — 구현 완료, 실제 패드 검증 대기

**선행:** 2단계의 정규화된 입력.

- `src/game/entities/Player.ts`에 논리 횡좌표 `courseX`와 플레이어 상태 구현.
- 자동 전진 속도, 가속·감속, 최대·최소 속도, 코스 경계 적용.
- 접지·상승·낙하와 점프 높이를 게임 상태로 관리.
- delta 기반 이동과 점프를 구현하고 튜닝 값은 `config/constants.ts`로 모음.

완료 조건: 임시 플레이어가 좌우로 움직이고 한 번 눌렀을 때 한 번 점프한다. 두 입력 장치에서 가감속을 포함한 조작이 동작한다. 프레임률이 달라도 이동·점프 시간이 일관된다.

여기서 조작 감각을 먼저 조정한다. 이후 모든 기능은 이 이동 모델을 공유한다.

구현 결과: Phaser에 의존하지 않는 `Player`가 논리 횡좌표·속도·누적 거리·접지/상승/낙하를 관리하고, `PlayerView`가 지평선을 바라보는 뒷모습을 그린다. 공통 입력을 실제 좌우 이동·가감속·점프에 연결했다. 양쪽 끝에는 날개와 그림자까지 남는 여백을 두며, 점프 시 몸체만 올라가고 그림자는 지면에 남는다. 전진 거리에 맞춰 달리기 동작을 갱신한다.

시간 정책: 초 단위 delta로 갱신하며 일반 프레임은 최대 50ms로 제한한다. 게임 화면의 포커스를 잃으면 이동·거리·점프를 함께 멈추고, 복귀 첫 프레임은 delta를 버린다. 가감속이 속도 한계에 도달한 프레임도 구간별로 거리를 적분한다.

자동 검증: 기존 입력 테스트 17개와 이동 테스트 9개가 통과했다. 30·60·144 FPS의 이동·거리·점프 일관성, 양쪽 경계, 아날로그 강도, 속도 한계, 짧은 탭 점프, 공중 재점프·held 자동 점프 방지, 긴 프레임 제한, 키보드 의도와 모의 표준 패드의 동일 이동을 확인했다. 실제 패드 조작은 하드웨어 검증 대기로 유지한다.

브라우저 검증: 내장 브라우저에서 실제 Space 입력으로 점프를 확인했다. 임시 검증 페이지의 지속 키 이벤트로 좌우 경계·가감속·점프 중 포커스 이탈과 재개를 확인했다. 1280 × 720, 390 × 844에서 오른쪽 끝의 공중 펭귄도 화면 안에 표시되었고 캔버스는 하나였다. 린트·타입 검사·프로덕션 빌드를 통과했으며 임시 검증 페이지는 제거했다.

## 4. 직선 코스와 원근 표현 — 구현 완료

`PerspectiveSystem`이 지평선·접촉 지점·위치·크기를 계산한다. `CourseView`의 눈 표시·코스 기둥과 박스, `PlayerView`가 같은 투영을 사용한다. 실제 전진 거리로 상대 거리를 줄이므로 3단에서 더 빠르게 접근한다.

## 5. 박스 장애물과 충돌 — 거리 기록 모드로 구현 완료

초기 장애물을 네온 정사각형 박스로 변경했다. 7개 후보 위치에 무작위 편차를 주고, 120m마다 한 줄의 개수를 1→6개로 늘린다. 예약한 빈 통로는 이전 줄과 같거나 한 칸 이웃하며 최고 속도에서도 도달 가능하다.

`CollisionSystem`은 프레임 전후 거리·횡좌표·점프 높이 구간으로 접촉을 검사해 통과 누락을 막는다. 박스 접촉은 즉시 게임오버이고 충분히 높은 점프로는 회피한다. 지나간 박스는 제거한다.

빠른 섬광 대신 고정된 네온색·X 무늬·느린 테두리 효과를 사용한다. 움직임 줄이기 설정에서는 효과를 끈다. 얼음 구멍·크레바스·물개는 후속 콘텐츠다.

## 6. 한 판 완성 — 거리 기록 모드 구현 완료, 실제 패드 검증 대기

기존 시간제 단일 스테이지 MVP를 현재 요청에 맞춰 무한 거리 기록 모드로 변경했다.

- 입력 없이 1단 자동 전진, 새 ↑/↓ 입력으로 1~3단 선택.
- `RunSystem`이 RUNNING → GAMEOVER와 실제 거리 점수를 소유.
- 이동 거리·최고 기록·속도 단수·난이도 HUD와 게임오버·다시 도전 UI.
- 접촉 시 거리 확정, 최고 기록 저장 실패 시 메모리 유지.
- 재시작 시 모든 주행 상태·입력·박스를 초기화하고 최고 기록 보존.
- 창/탭 이탈 시 전체 일시정지, 복귀 delta 폐기. 일반 프레임은 최대 50ms.
- 게임 영역 포커스는 입력에만 적용하며 자동 전진은 계속됨.

현재 모드의 한 판 흐름은 완성했다. 검증 세부 사항은 [거리 기록 모드 계획](ENDLESS_RUN_PLAN.md)을 따른다. 실제 게임패드 및 브라우저 교차 검증은 남아 있다.

### 원래 시간제 스테이지 계획의 조정

StageSystem, 제한 시간, 목적지, 클리어 보너스, 피격 감속·갇힘은 **후속 별도 스테이지 모드**로 남긴다. 현재 거리 기록 모드에 상충하는 즉사/감속·무한/목적지 규칙을 섞지 않는다. 추후 구현할 때 현재 입력·Player·원근·충돌을 공유하고 모드별 종료 규칙을 구분한다.

## 7. 콘텐츠와 후속 개선

**선행:** 6단계 MVP의 입력·충돌·재시작 검증 완료.

랜드마크 10종과 NEXT HUD는 구현 완료했다. 이후의 최신 작업 순서는 [코스 확장 계획](COURSE_EVOLUTION_PLAN.md)을 따른다: 거리 구간과 박스 생성 연결 → 실제 장애물·회복 규칙 → 아이템·점수 → 커브 → 날씨·사운드. 아래 목록은 이전 확장 후보 기록이다. 현재 단계에서는 실행 중인 즉사 규칙을 유지하며, 회복 규칙과 종료 조건은 해당 구현 단계에서 함께 전환한다.

1. 자체 제작 펭귄·배경·장애물 아트와 애니메이션 교체.
2. 깃발·물고기 수집, 목적지 기지, 추가 스테이지·난이도 데이터 확장.
3. 음악·효과음, 음소거·볼륨, 컨트롤러 안내 개선.
4. 곡선 코스, 비행 파워업, 눈·파티클·피격 연출을 필요에 따라 추가.
5. 성능을 측정해 병목 개선. 필요한 경우 오브젝트 풀링 적용.
6. **모바일·태블릿 버튼 구현 완료:** 반투명 좌우·점프·감속·가속 버튼을 같은 InputManager에 연결. 멀티터치·pointer capture와 취소·회전·재시작 정리. 긴 변/짧은 변이 1.35 이상인 세로 화면만 90도 회전하고 정사각형에 가까운 화면과 가로 화면은 원래 방향을 유지. 기존 16:9 배치는 CSS가 관리하고 Phaser 논리 해상도는 유지.

완료 조건: 추가 콘텐츠가 기존 키보드·게임패드 조작과 게임 종료·재시작 흐름을 깨뜨리지 않는다. 각 기능은 별도 작업 단위로 진행한다.

## 공통 검증

- 코드 변경 시 린트, 타입 검사, 프로덕션 빌드와 해당 동작의 브라우저 확인.
- 입력 병합·deadzone·점프 edge, 충돌·종료 상태처럼 회귀 위험이 있는 로직은 의미 있는 자동 검증 추가.
- 데스크톱 Chrome, Edge, Safari, Firefox를 지원 대상으로 두고 실제 확인한 환경을 기록.
- 새 단계마다 필요한 파일만 생성. 미래 구조를 위한 빈 파일·라이브러리는 추가하지 않음.
- 아트와 확장 기능보다 조작 반응성·판정 가독성·한 판의 완결성을 우선.
