# 고속 점프 실제 플레이 점검

아래 원인 분석은 수정 전 점프 높이 150, 최대 이동 거리 30m, 장애물 20% 축소 상태의 기록이다. 후속 수정과 재검증은 마지막 절에 정리했다. 실제 브라우저의 키보드 입력으로 점검했고 속도·장애물·게임 상태를 강제로 주입하지 않고 ↑로 가속하고 Space로 점프했다. 관찰 사이에는 일시정지를 사용했으며, 연속 입력 구간은 실제 게임 루프로 진행했다.

## 실제 브라우저 결과

1280×800 데스크톱 화면, 로컬 프로덕션 빌드의 `?debugInput=1`에서 HUD와 입력·점프 표시, 화면을 함께 확인했다.

| 주행 | 도달 속도 | 결과 |
| --- | --- | --- |
| 1 | 10회 가속, 94m/s | 물개 앞에서 점프했지만 먼저 착지했고 약 0.221km에서 충돌했다. 점프 중 추가로 누른 입력도 표시됐지만 새 점프는 시작되지 않았다. |
| 2 | 13회 가속, 118m/s | 가속하면서 반복 점프했지만 약 0.271km에서 상자에 접지 충돌했다. |
| 3 | 20회 가속, 174m/s | 10~20회 가속 구간에서 점프를 반복했다. 174m/s에 도달한 뒤 Space를 추가로 8회 입력했으며 약 1.281km에서 충돌했다. 입력 후 화면을 관찰할 때는 점프가 이미 끝나 접지 상태로 보였다. |

입력 디버그의 점프 눌림 누계는 세 주행에서 20회였다. 이는 입력 횟수이며, 공중에서 무시된 입력도 포함하므로 성공한 점프 20회라는 뜻은 아니다. 자동화 도구의 조작·캡처 간격은 사람의 반응 시간과 다르므로 플레이 난이도의 정량적 사용자 평가로 해석하지 않는다. 아래 체공 시간은 화면 캡처 시간으로 추정한 값이 아니라 현재 코드의 계산식이다.

## 원인

수정 전 `src/game/entities/jump.ts`는 `min(0.8초, 30m / 현재 속도)`를 사용했다. 최대 높이를 늘려도 시간 제한은 그대로였다.

| 기본 속도에서 가속 횟수 | 속도 | 점프 시간 | 60FPS에서의 프레임 수 |
| --- | --- | --- | --- |
| 0 | 14m/s | 0.800초 | 48 |
| 10 | 94m/s | 0.319초 | 약 19 |
| 15 | 134m/s | 0.224초 | 약 13 |
| 20 | 174m/s | 0.172초 | 약 10 |

- 점프가 30m 안에 끝나므로 장애물보다 너무 일찍 뛰면 앞에서 착지한다. 속도를 올릴수록 같은 거리의 입력 여유가 더 짧은 시간으로 압축된다.
- `Player.update()`는 접지 상태의 새 점프 입력만 받는다. 착지 직전에 누르면 입력은 들어와도 버려진다. 공중 가속은 남은 점프 시간도 줄인다.
- 기존 장애물 테스트는 정확한 시작 거리에서 점프하고 다음 입력 시각에 맞춰 시뮬레이션 프레임을 나눈다. 충돌 계산의 일관성은 검증하지만 사람이 보고 누를 시간이나 충분한 체공 시간을 보장하지 않는다.

## 수정 방향

높이를 다시 늘리는 대신 고속에서도 충분한 체공 시간을 확보해야 한다. 예를 들어 0.7~0.8초를 유지하고 착지 직전의 짧은 입력을 다음 점프로 이어주는 방식을 검토할 수 있다. 이 경우 고속에서 한 점프로 여러 장애물 행을 넘을 수 있게 된다.

무제한 속도, 고정 35~55m 행 간격, 한 행보다 짧은 점프 거리, 충분한 체공 시간을 모두 유지할 수는 없다. 초기 점검에서는 추가로 게임 규칙을 변경하지 않았고, 이후 사용자 수정 요청에 따라 아래 체공 시간 우선 방식을 적용했다.

## 적용한 수정과 재검증

- 모든 속도에서 체공 시간을 0.8초로 고정했다. 최대 높이 150을 유지하며, 공중 가감속으로 궤적이나 남은 시간이 압축되지 않는다. 30m 거리 제한을 제거해 고속에서는 한 점프로 여러 행을 넘을 수 있다.
- 착지 전 0.12초 안의 새 입력은 한 번 저장했다가 착지 즉시 다음 점프로 이어진다. 같은 프레임의 남은 시간도 다음 점프에 반영한다. 이른 공중 입력은 무시하고 누른 채 자동 반복은 하지 않는다.
- 충돌은 착지·다음 점프의 두 포물선을 같은 기준으로 계산한다. 입력을 저장했어도 착지 순간 구멍에 닿거나 상승 중 장애물 높이를 넘지 못하면 정상 게임오버다. 충돌 시점의 거리·주행 시간·평균도 보존한다.
- 일시정지, 포커스·창 이탈, 크기 변경, 랜드마크 도착, 게임오버, 재시작 때 저장된 입력을 정리한다.
- 전체 테스트 115개, 린트, 타입 검사, `pnpm build --webpack` 통과. 20/30/60/144 FPS의 고정 체공 시간, 94/134/174m/s 이상 속도, 장애물 6종·다중 행 통과, 착지 입력 경계, 한 프레임 안의 착지·다음 상승과 정확한 충돌 시점, held 반복 방지를 포함한다.
- 새 프로덕션 빌드의 실제 키보드 조작으로 다시 10회 가속(94m/s), 20회 가속(174m/s)을 확인했다. 94m/s에서 상승·정점이 연속 화면에 보였고, 174m/s에서도 상승·하강을 관찰하며 물개와 상자를 넘고 다음 점프를 이어갔다. 약 0.818km까지 주행을 확인 후 일시정지했다. 별도 시도에서는 실제 착지 충돌과 게임오버·재도전도 확인했다. 검증 구간 브라우저 console error/warning은 없었다.

실물 게임패드는 직접 조작하지 않았으며 공통 입력·모의 패드 테스트로 확인했다. 브라우저 화면 관찰과 별개로 정확한 0.8초 및 0.12초 경계값은 시뮬레이션 테스트로 검증했다.
