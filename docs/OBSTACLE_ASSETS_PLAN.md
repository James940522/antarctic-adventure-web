# 남극 장애물 13종 통합

## 현재 최종 사양 — 2026-09-23, 13종 확장

이 절이 아래의 6종 초기 통합·배치 기록보다 우선한다. 구현과 검증의 상세 보고는 [13종 확장 보고](OBSTACLE_EXPANSION_REPORT.md)를 참고한다.

- 기존 7개 레인과 Phaser 의사 3D 구조를 유지한다. 1칸은 7종, 인접 2칸은 5종, 전체 폭 바리케이드는 1종이다.
- 각 장애물은 `startLane`, `occupiedLanes`를 저장한다. 같은 점유 영역에서 중심, 그림 크기, 충돌 폭과 높이를 한 번 계산하여 CourseView·CollisionSystem·ItemSystem·debug가 공유한다.
- 1칸: 눈더미·상자·바위·구멍·얼음 송곳·연료 드럼통·빙판. 2칸: 크레바스·물개·부서진 썰매·추락 안테나·방풍 울타리. groundHazard는 구멍·크레바스·빙판이며 지면에서만 충돌한다.
- `laneSpan: "full"`은 런타임 레인 수 전체, 시작 레인 0, 트랙 중앙이다. 한 이미지가 전체 폭을 가로막는다. 2026-09-24에 사용자가 제공한 가로로 긴 바리케이드 PNG(2172×724)로 교체했고, 투명 여백을 제외한 프레임 `[16, 410, 2141, 234]`의 원본 비율을 유지한다. 이전 세로 30% 압축은 제거했다. 접촉 지점에서 약 909×99px로 표시되어 점프 최대 높이 150px보다 낮다. 접지 상태에서 좌우 끝으로 우회할 수 없고, 실제 점프 높이가 충돌 높이 72를 넘어야 통과한다. 기존 Ghost Penguin 효과는 전체 폭 장애물에도 유지된다.
- 일반 묶음은 기존 2/3/4개 단계와 6~12m 엇갈림, 공통 회피 레인을 유지한다. 바리케이드는 반드시 단독 묶음이다. 바리케이드 또는 넓은 종류를 다음 묶음으로 미루면 현재 묶음이 한 개로 끝날 수 있다.
- 기본 묶음 간격은 마지막 장애물 기준 35~55m, 2칸을 포함하면 45~65m, 바리케이드 뒤는 55~75m다. 바리케이드 앞도 최소 55m를 확보한다.
- 속도가 높으면 일반 간격은 `속도 × (0.35초 + 한 레인 이동 시간) + 충돌 깊이 3.2m` 이상, 바리케이드 전후는 `속도 × (0.8초 + 0.35초) + 3.2m` 이상으로 늘린다. 시야는 기본 120m이며 고속에서 최소 1.65초 앞을 보여준다. 이미 보여준 장애물의 위치는 바꾸지 않으므로 무리한 연속 가속은 플레이어가 판단해야 한다.
- 점유 폭 bag은 30슬롯(1칸 18 / 2칸 10 / full 2)이다. 각 폭 안에서 종류 shuffle bag을 사용한다. 체감 빈도는 약 60% / 33.3% / 6.7%다. 동일 종류 연속 출현을 막고 바리케이드 사이에 일반 장애물을 최소 3개 둔다.
- 첫 50m 동안 장애물을 표시하지 않는다. 랜드마크 안전 구간은 종류를 버리지 않고 다음 안전 거리로 미룬다. 재도전은 bag·위치 횟수·시야·진행 상태를 초기화한다.
- PNG 13개는 기존 BootScene 루프에서 전부 preload하며 누락 시 초기화에 실패한다. 사용자 지시에 따라 파일명은 `fuel-drums.png`, `ice-patch.png`로 정정했다. 이미지 픽셀은 변경하지 않았다.
- `?debugObstacles=1`: 청록 그림 경계, 녹색 점유 레인, 빨강 solid/주황 groundHazard 판정과 종류·laneSpan·레인 번호를 표시한다. 프로덕션에서는 제거된다.
- 개발용 고정 장면: `?debugObstacles=1&debugObstacle=barricade&debugPlayerX=-1&debugJump=1`. `debugPlayerX=-1/0/1`로 좌/중/우, `debugJump=1`로 실제 프레임 루프에 한 번의 자동 점프 입력을 준다. 생략하면 수동 조작이다. 2칸은 `debugStartLane=0..5`로 확인한다. 이 경로는 검증 전용이며 자동 테스트 판을 온라인에 저장하지 않는다.

## 현재 배치 규칙 — 2026-09-23 추가 조정

사용자 요청에 따라 한 행 하나 규칙을 앞뒤로 엇갈린 묶음 배치로 변경했다. 이 절이 아래 초기 통합 기록의 배치 규칙보다 우선한다.

- 초반 2개, 배치 거리 2km부터 최대 3개, 5km부터 최대 4개를 생성한다. 묶음 내부에서는 각 장애물을 6~12m씩 앞뒤로 띄운다.
- 1칸/2칸별 시작 위치 사용 횟수를 기록해 덜 사용한 위치를 우선하고, 동률이면 무작위로 선택한다. 사이드에 몰리는 현상을 줄이며 좌우·중앙을 고르게 사용한다.
- 묶음 내부의 점유 칸은 겹치지 않고 공통 회피 레인을 최소 하나 남긴다. 넓은 종류 때문에 7개 레인을 모두 쓰게 되면 마지막 종류를 다음 묶음으로 미룬다. 4개 구간에서도 조합에 따라 3개가 나올 수 있다.
- 30m/s·반응 여유 0.35초와 실제 횡이동 속도로 다음 묶음의 회피 공간까지 이동 가능한 경로를 남긴다. 넓은 종류나 회피 경로가 막히면 다른 위치 조합을 선택한다.
- `nextGroupDistance`는 월드 단위다. 마지막 장애물부터 다음 묶음까지 35~55m, 직전 묶음에 물개/크레바스가 있으면 45~65m를 띄운다.
- 첫 50m 시야 안전 구간과 6종 순환을 유지한다. 랜드마크 안전 구간과 겹칠 수 있는 묶음은 통째로 건너뛰며 종류·위치 사용 횟수를 소진하지 않는다.
- 재시작 때 거리 스케줄·종류 bag·미룬 종류·위치 사용 횟수·회피 경로를 함께 초기화한다.

80개 seed에서 8km까지 개수 단계, 앞뒤 간격, 레인 중복 방지, 공통 회피 공간, 30m/s 횡이동 경로, 짧은 구간의 위치 균형을 검증했다. 350km 생성에서도 각 시작 위치의 사용 횟수 차이가 작게 유지되는지 검사한다. 전체 142개 테스트, 린트·타입 검사·프로덕션 빌드가 통과했다. 프로덕션 브라우저에서 초반의 엇갈린 장애물 렌더링과 접촉 게임오버를 확인했으며 콘솔 오류·경고는 없었다. 2km/5km 밀도 단계는 시뮬레이션으로 검증했다. 아래는 초기 구현과 이전 검증 기록이다.

## 데이터와 배치

`src/game/data/obstacles.ts`가 이미지·한국어 이름·점유 칸·충돌 종류·크기를 관리한다. `supply-create.png`는 요청대로 `supply-crate.png`로 변경했고, 이미지 자체는 편집하지 않았다. PNG의 희미한 잔여 픽셀과 투명 여백을 제외한 실제 그림 범위를 기존 랜드마크처럼 texture frame으로 등록한다.

| ID | 점유 | 판정 | 특성 |
| --- | --- | --- | --- |
| snow-drift | 1칸 | solid | 가장 낮고 관대한 판정 |
| supply-crate | 1칸 | solid | 표준 판정 |
| ice-rock | 1칸 | solid | 높아 보이는 그림의 하단만 판정 |
| ice-hole | 1칸 | groundHazard | 파편을 제외한 중앙 폭, 지면만 판정 |
| crevasse | 인접 2칸 | groundHazard | 중앙 위험 폭, 지면만 판정 |
| seal | 인접 2칸 | solid | 정지한 물개 하나, 점프 가능 |

한 칸은 기존 레인 중심 간격 0.3이다. 2칸의 중심은 두 인접 레인 중심의 평균이고, 가능한 시작 위치는 0~5다. 1칸은 0~6 모두 같은 확률로 선택한다. 6종을 한 번씩 섞어 소진하며, 새 bag의 첫 종류가 이전 마지막 종류와 같으면 교환한다. 생성 시에만 RNG를 사용한다.

첫 **50m 주행까지 아무 장애물도 보이지 않는다.** 기존 시야가 120m이므로 첫 장애물의 배치 거리는 170m이고, 플레이어가 50m에 도달할 때 지평선에 들어온다. 기본 행 간격은 35~55m, 직전 물개/크레바스 뒤에는 45~65m다. 랜드마크 안전 구간은 계속 비우며, 건너뛴 행은 shuffle bag을 소진하지 않는다.

## 렌더링과 판정

크기는 `레인 간격 × 점유 칸 × visualScale`이며, 프레임의 종횡비를 유지해 `setScale` 하나로 확대한다. 점프 타이밍 조정과 함께 6종의 `visualScale`을 각각 20% 줄였다(눈더미·상자 0.72, 바위 0.76, 구멍·크레바스·물개 0.8). 2칸도 이미지 하나만 사용한다. 하단 중앙을 원근 투영된 지면에 맞추며, Phaser `pixelArt: true`로 nearest-neighbor 필터링을 적용한다.

실제 충돌 폭은 시각 폭보다 좁다. solid 높이는 이미지 높이의 하단 일부이며 전부 최대 점프 높이 150보다 낮다. 그림 축소에 맞춰 판정 폭·높이도 20% 줄었다. groundHazard는 높이 0이므로 발이 지면에서 떨어지면 통과한다. 종방향 판정 깊이는 모든 종류에서 ±2m에서 ±1.6m로 줄였다. 2칸이 점프 지속 시간을 늘리지 않는다. 고속 관통·횡이동 진입·착지 판정은 기존 swept collision을 계속 사용한다.

고속 점프 보완: 높이 150에 이어 최대 이동 거리 제한도 제거했다. 94/134/174m/s에서도 점프는 동일하게 0.8초이며, 공중 가감속은 전진 거리에만 반영한다. 고속에서는 한 점프로 여러 행을 넘을 수 있고 35~55m 생성 간격은 유지한다. 착지 전 0.12초 안의 새 입력은 한 번 저장해 착지 직후 이어서 점프한다. 이른 공중 입력과 누른 채 자동 반복은 허용하지 않는다. 일시정지·포커스 이탈·크기 변경·도착·종료 때 입력 저장을 정리한다. `entities/jump.ts`의 포물선과 프레임 시작/끝 진행도, 같은 프레임 안의 착지·다음 점프를 `CollisionSystem`에서도 사용한다. 착지 지면이나 낮게 상승 중인 몸이 장애물에 닿으면 여전히 정상 충돌한다.

`CourseView`는 live id의 이미지 한 개를 재사용하고 지난 이미지를 제거한다. 프레임마다 종류 데이터·이미지·shuffle 배열을 새로 만들지 않는다. 재시작은 목록·거리 스케줄·bag·뷰를 함께 초기화한다.

`BootScene`에서 6종을 모두 사전 로드한다. 장애물 파일을 못 읽으면 게임 초기화 오류를 표시해 보이지 않는 장애물과 충돌하는 상황을 막는다. 랜드마크 경로는 `/asset/img/landmark/`, 장애물은 `/asset/img/obstacle/`다.

개발 환경의 `?debugObstacles=1`은 축소된 실제 판정 폭·깊이와 solid 높이를 표시한다. 프로덕션 번들에는 이 옵션의 디버그 표시 분기가 포함되지 않는다.

## 검증

- 최신 수정은 모든 속도에서 체공 0.8초, 착지 전 0.12초 입력 저장을 적용했다. 전체 115개 테스트와 린트·타입 검사·`pnpm build --webpack` 통과. 실제 브라우저에서도 10회·20회 가속(94/174m/s) 후 점프 상승·하강, 장애물 통과와 다음 점프를 확인했다. 이전 거리 제한의 문제와 수정 결과는 `docs/HIGH_SPEED_JUMP_REVIEW.md`에 기록했다.
- 점프 높이 150·최대 거리 30m·장애물 20% 축소 조정 후 전체 107개 테스트와 린트·타입 검사·`pnpm build --webpack`을 통과했다. 기존에는 24m 앞에서 점프하면 착지하며 충돌하는 사례를 재현했고, 6종 × 6개 고속(38~1022m/s) × 4개 입력 거리(6/12/18/24m) × 4개 프레임률(20/30/60/144 FPS)의 576개 조합에서 통과를 확인했다. 최소 35m 행 간격의 재점프와 실제 접촉 시 게임오버도 유지된다. 브라우저에서는 62m/s 점프 렌더링, 축소된 장애물, 1024×320 모바일 터치 점프의 상승·하강·착지와 화면 여백을 확인했으며 console error/warning은 없었다. 아래는 이전 구현 단계의 검증 기록이다.
- 전체 테스트 84개 통과. 이전 다중 박스 규칙 테스트 2개는 새 생성 규칙 테스트로 교체했다.
- 80개 RNG seed에서 60개씩 생성: 각 종류 정확히 10회, 매 6개는 6종 한 번씩, 경계 중복 없음.
- 행 간격, 시작 50m 안전 구간, 생성 업데이트 간격 독립성, 모든 레인/인접 쌍의 분포, 트랙 범위, 활성 오브젝트 수 제한 검증.
- 6종 모두 접지 충돌, 14/22/30m/s와 30/60/144 FPS에서 한 번의 점프 회피, 고속 연속 충돌·착지·횡이동 검증.
- 고속 점프 보완 후 전체 92개 테스트 통과. 6종과 14~1022m/s, 20/30/60/144 FPS에서 단일 점프 회피 및 35m 간격 3개 행 연속 점프를 검증했다. 공중 가감속, 점프 높이 유지, 누른 채 재점프 방지, 한 프레임 안의 이륙·착지, 구멍 안 착지와 다음 미회피 장애물의 정확한 충돌 거리·시간을 포함한다.
- 브라우저에서 62m/s로 가속 후 점프 상승·접지·다음 점프가 렌더링됨을 확인했다. 일시정지와 재시작도 정상 동작했으며 console error는 없었다. 고속 수치·프레임률 조합은 시뮬레이션 테스트로 검증했다.
- 6종 모두 하나의 이미지로 렌더링되고 비율·하단 기준점을 유지하며 반복 프레임에 재사용, 제거/재시작 때 정리됨을 렌더러 단위 테스트로 검증.
- 기존 10개 랜드마크의 안전 구간·정확한 도착·2.5초 축하·거리/평균·일시정지·재시작 회귀 테스트 통과. 이미지 10개는 기존 파일과 같은 해시다.
- 브라우저에서 시작 직후 빈 코스, 실제 PNG의 원근 확대와 판정 표시, 충돌 게임오버, 재도전, 일시정지/재개, 844×390 모바일 터치 패드 배치를 확인했다. 검증 구간 console error 없음.
- 린트·타입 검사·`pnpm build --webpack` 통과. production chunk에서 `debugObstacles` 분기가 제거된 것을 확인했다.

실물 휴대폰·게임패드 검증은 남아 있다. 제공된 크레바스의 세로로 길게 그려진 구도도 원본 비율 그대로 사용하며, 게임에서의 2칸은 횡방향 점유만 뜻한다.

## 후속 CourseSegment 확장 지점

이번에는 CourseSegmentSystem을 구현하지 않았다. 나중에는 `ObstacleSystem`의 bag 재충전 시 허용 종류를 제한하고, 다음 행 간격을 계산할 때 구간 배율을 적용하면 된다. 타입 정의·뷰·충돌 시스템은 그대로 재사용할 수 있다. 허용 종류가 바뀔 때 bag을 갱신하는 정책과 랜드마크 안전 구간 우선순위는 별도로 검증한다.
