# 아이템 시스템 / Ghost Penguin

첫 아이템은 사용자 PNG `/asset/img/item/item_ghost_penguin.png`를 그대로 사용한다. 이미지 파일은 수정하지 않으며 Phaser texture frame으로 투명 여백만 제외한다.

## 구성과 확장

- `src/game/data/items.ts`: 아이템 종류, 에셋·표시 크기·획득 판정, 효과 연결, 스폰·고스트 설정.
- `src/game/systems/ItemSystem.ts`: 거리 기반 생성, 레인 선택, 연속 이동·점프 궤적에 따른 획득, 제거·초기화.
- `src/game/systems/ItemEffectSystem.ts`: 효과 종류별 남은 시간과 모든 효과에 공통으로 적용되는 보류 상태. 같은 효과는 지정 시간으로 갱신하며 다른 효과의 시간을 지우지 않는다. 고스트 투명도와 마지막 5초 숫자는 활성 효과 시간에서 파생한다.
- `src/game/systems/RunContactSystem.ts`: 프레임 내부의 획득 → 효과 종료 → 장애물 접촉을 실제 시간 순서대로 처리한다. 같은 순간의 획득과 충돌은 획득을 먼저 처리하며, 보호 효과가 없는 아이템이면 같은 순간의 장애물을 다시 검사한다.
- `src/game/systems/ItemView.ts`: 기존 `PerspectiveSystem`을 사용한 PNG·광륜·별빛 렌더링과 카운트다운. React 상태나 별도 타이머를 추가하지 않는다.
- `BootScene`, `GameScene`, `PlayerView`, `RunSystem`, `CollisionSystem`: 로드·게임 수명 주기·표현·공통 연속 판정 연결.
- `items.test.ts`, `ItemEffectSystem.test.ts`: 생성·획득·시간·충돌·랜드마크 보류/복원·초기화 회귀 테스트. `obstacles.test.ts`의 독립 장애물 테스트는 아이템 생성을 비활성화한다.

새 아이템은 `ITEM_TYPES`와 `ITEM_DEFINITIONS`에 정의한다. 새로운 효과 종류는 `ItemEffectType`과 `ItemEffectSystem`에 추가하고, 필요한 능력/렌더링 소비 지점에 연결한다. **능력과 시각 표현은 반드시 `activeSeconds(type)`을 사용한다.** 보존된 시간을 확인하는 `remainingSeconds(type)`은 보류 중에도 값을 반환하므로 효과 발동 여부 판단에 사용하지 않는다. 로더·스폰·획득 경로와 랜드마크 보류 처리는 모든 종류가 공통으로 사용한다. 고스트 상태도 다른 아이템 획득을 차단하지 않는다. 테스트 전용 두 번째 효과로 동시 획득, 독립적인 시간 유지, 공통 보류와 복원을 검증한다.

## 초기 등장 빈도

- 첫 생성 위치와 이후 생성 간격을 매번 **3,000~4,000m 범위에서 무작위로 한 번씩** 뽑는다. 평균 약 3.5km에 하나이며, 고정된 100m 단위의 확률 추첨은 사용하지 않는다.
- 생성된 아이템 위치에서 다음 간격을 계산한다. 먹었는지 여부와 프레임 수에 영향을 받지 않고, 다음 생성 거리까지 기다리는 동안 다시 추첨하지 않는다. 새 게임에서는 첫 위치도 새로 정한다.
- 기본 시야 120m보다 간격이 길어 일반 주행에서는 한 화면에 하나만 나타난다. 고속에서는 코스와 같은 확장 시야를 사용한다.
- 같은 레인의 장애물과 앞뒤 12m 이내로 겹치지 않게 배치한다. 2칸 장애물의 실제 폭도 반영한다.
- 장애물 양옆을 확인할 수 있도록 12m의 생성 여유를 확보하며, 아이템은 기본 속도에서 예정된 위치의 약 108m 전방, 고속에서는 확장 시야 거리에서 12m를 뺀 전방부터 표시한다.
- 예정 위치가 랜드마크 안전 구간이거나 모든 레인이 막혀 있으면 10m씩 뒤로 미뤄 처음 안전한 곳에 놓는다. 이 예외에서는 간격이 4km보다 길어질 수 있지만, 추가 3~4km 전체를 기다리지는 않는다. 장애물 종류·행 간격·레인 규칙은 변경하지 않는다.

## 발견하기 쉬운 표시

아이템 표시 범위는 `PerspectiveSystem.viewDistance`와 일치시켜 고속에서도 기존 120m 안으로 들어올 때까지 숨겨지지 않게 한다. 이미지 폭은 논리 화면 기준 최소 32px을 보장하고, 하단 위치·깊이 순서는 기존 원근 투영을 따른다. 빨간 테두리는 논리 화면 기준 1px이며, 이미지 바로 둘레에만 옅은 반투명 광륜(불투명도 6~12%)을 둔다. 어두운 자주색 받침 배경으로 흰 눈과 구분하고, 흰 중심을 가진 빨간 별 세 개가 각각 1.8초 주기로 크기·밝기를 부드럽게 바꾸며 번갈아 반짝인다. 이미지 자체는 점멸하지 않는다. 표시 크기 보정은 획득 판정·생성 간격·효과에 영향을 주지 않는다.

반짝임은 실제 주행 시간을 사용하므로 수동 일시정지·창 이탈·랜드마크 정지 중 멈춘다. `prefers-reduced-motion`에서는 광륜과 별을 정적으로 유지한다. 획득·통과 후 제거·게임오버·재시작·게임 해제 때 이미지와 장식도 함께 정리한다.

## 고스트 시간과 충돌

획득 시 10초로 설정하고 다시 획득하면 남은 시간을 10초로 갱신한다. 누적하지 않는다. 다른 효과는 유지한다. RunSystem과 같은 제한된 delta를 사용하고, 획득 프레임에서는 접촉 이후 시간만 차감한다. 수동 일시정지·창 이탈 중에는 시간과 경고 애니메이션이 함께 정지한다. 게임오버·재시작은 효과·보류 상태·예외 장애물·아이템을 모두 정리한다.

랜드마크에는 모든 아이템에 적용하는 별도 보류 수명 주기가 있다. 도착 프레임에서 실제 도착까지의 시간만 차감한 뒤 `setSuspended(true)`로 모든 효과를 보류한다. 저장된 시간은 그대로 남고, `advance()`도 보류 중에는 차감하지 않는다. `activeSeconds()`가 0을 반환하므로 능력이 비활성화되고, 펭귄은 정상 불투명 상태로 축하하며 깜빡임과 카운트다운도 숨긴다. 2.5초 축하가 끝나 재출발하는 프레임에 `setSuspended(false)`로 한꺼번에 복원한다. 예를 들어 3.8초가 남았다면 재출발 때도 3.8초이며, 경고 숫자와 깜빡임은 이전 단계부터 이어진다. 축하 중 일시정지했다가 돌아와도 먼저 축하를 마친 뒤 복원한다. 도착 순간 이미 만료된 효과는 되살리지 않는다.

남은 시간이 5초보다 많으면 펭귄 alpha 0.55만 적용한다. 마지막 5초에는 숫자 5→1을 화면 높이 27%의 중앙에 표시하고, 처음 등장할 때 0.8→1.15→1 크기로 움직인다. alpha는 0.55와 1 사이에서 전환하며, 전환 간격이 0.5초에서 0.12초로 줄어든다. `prefers-reduced-motion`에서는 깜빡임·크기 효과 없이 반투명과 숫자만 표시한다. 0초에 alpha 1로 복귀하고 숫자를 숨긴다.

고스트가 활성화되면 장애물 판정만 건너뛰며 아이템 획득은 계속 검사한다. 끝나는 정확한 시점에 종방향·횡방향·높이가 실제로 겹친 장애물 ID만 예외 목록에 넣는다. 그 장애물이 뒤로 지나갈 때까지 예외를 유지하고 이후 제거한다. 종료 이후 새로 진입한 장애물은 같은 프레임에서도 정상 판정한다. 공중에 있어 겹치지 않았던 장애물에는 예외를 주지 않는다. 기존 포물선 점프와 착지 후 이어지는 점프를 그대로 판정한다.

점수 배수·보너스·속도 변화는 없다. 거리와 실제 주행 시간, 평균 속도와 기존 SCORE 공식을 그대로 사용한다.

## 검증

자동 검증은 `pnpm test`, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`로 실행한다. 아이템 테스트는 30/60/144 FPS의 10초 지속시간, 거리 기반 생성, 고속 획득 순서, 6종 장애물 통과, 재획득, 동시 효과, 종료 시 겹침 예외, 일시정지·축하·재시작을 포함한다.

로컬 브라우저의 실제 GameScene/Phaser 렌더러에서도 원근 접근, 획득 제거·반투명화, 마지막 5초 숫자, 재획득의 숫자 제거, 0초의 원상복구, 종료 시 겹침 생존과 이후 새 장애물 충돌을 확인했다. 검증용 임시 페이지는 제거했다. 실제 게임패드 하드웨어 검증은 수행하지 않았다.

2026-09-23 최신 검증 결과: 전체 테스트 141개, lint, TypeScript 검사와 `pnpm build --webpack` 통과. 3~4km 간격의 무작위성·안전 구간 이연·고속 생성·재시작을 검증했다. 공통 보류 테스트는 여러 효과의 동시 보류, 30/60/144 FPS의 정확한 도착 시점, 축하 중 수동 일시정지, 같은 잔여 시간 복원, 도착과 동시에 만료된 효과와 재시작을 포함한다. 실제 Phaser 화면에서 5.975초와 3.975초를 보존한 채 정상 불투명 상태로 축하하고, 출발 시 반투명·경고 숫자가 복원됨을 확인했다. 검증용 임시 페이지는 제거했다.

초기 구현 검증에서는 일반 메뉴 → 클래식 → 일시정지 → 메뉴 3회 전환에서 게임 중 캔버스 1개, 메뉴에서 0개를 확인했다. 기본 `pnpm build`는 이 실행 환경의 내부 포트 생성 제한(`Operation not permitted`)으로 Turbopack이 실패했으며, `pnpm build --webpack`과 `pnpm start`의 프로덕션 화면에서 클래식 진입과 일시정지·메뉴 복귀를 확인했다. 프로젝트의 기본 빌드 설정은 변경하지 않았다.
