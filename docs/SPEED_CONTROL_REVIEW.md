# 속도 조절·접근 움직임 점검 (2026-09-24)

## 원인과 변경

- 기존 `Player`는 입력 방향이 바뀌는 순간에만 선택 속도를 8m/s 변경했다. OS 키 반복과 무관하게 길게 누르면 추가 가속되지 않는 구현이었다.
- 자동 증가는 정상이며 실제 주행 초당 0.01m/s다. 입력 없이 1분 후 14.6m/s, 5분 후 17m/s가 된다. HUD 소수 첫째 자리 변화는 약 10초 간격이라 느리게 보일 수 있다.
- 수동 속도를 순간적으로 바꿔 전진량이 계단식으로 달라졌다. 또한 약 72.7m/s를 넘으면 `ObstacleSystem.viewDistance`가 속도와 함께 달라지고 원근 분모에도 적용되어 기존 장애물의 위치·크기가 변했다. 감속 때는 먼 오브젝트가 사라졌고, 초고속에서는 눈길 표시 간격도 재배열됐다.

현재 방향키·W/S·패드 스틱·D-pad·터치 버튼을 누르는 동안 수동 가속분을 **초당 ±8m/s** 조절한다. 기본 속도 증가는 함께 적용된다. 14m/s에서 ↑를 1초 누르면 22.01m/s, 2초면 30.02m/s다. 놓으면 수동 가속분을 유지하며 ↓는 현재 기본 속도까지만 내린다. 속도 상한은 없다. 일시정지·창 이탈·랜드마크 축하 중에는 두 증가분 모두 멈춘다.

`speed-motion.ts`가 가감속 중 이동 거리와 프레임 내부 속도를 계산한다. 감속 도중 기본 속도에 닿으면 그 전후 구간을 나눠 적분한다. 충돌·아이템 획득·랜드마크 도착은 거리 비율을 실제 시간 비율로 환산한다. 점프 궤적·효과 시간·평균 속도도 같은 접촉 시간을 사용한다.

원근 투영은 속도와 분리했다. 96m 안쪽은 기존 곡선을 유지하고, 먼 구간은 경계에서 위치와 접근률이 연속인 곡선으로 지평선까지 연장한다. 속도에 따른 시야 확장은 생성·표시 범위에만 쓰고 한 판 안에서 감속으로 줄이지 않는다. 기존 오브젝트가 뒤로 움직이거나 갑자기 커지고 사라지는 현상을 막는다. 눈길 표시는 고정된 월드 간격을 사용하고 랜드마크 투영도 속도와 무관하게 계산한다.

## requestAnimationFrame 판단

설치된 Phaser 4.2.1의 `src/dom/RequestAnimationFrame.js`, `src/core/TimeStep.js`와 현재 게임 설정을 확인했다. Phaser는 이미 단일 requestAnimationFrame 루프와 delta 평활화를 사용하며 `forceSetTimeOut`은 기본 false다. 추가 루프·React 프레임별 상태 업데이트·setInterval·setTimeout 기반 주행은 도입하지 않았다. 기존 루프 안에서 시간 기반 가감속과 일관된 투영을 사용한다.

- [Phaser RequestAnimationFrame](https://docs.phaser.io/api-documentation/class/dom-requestanimationframe): 화면 갱신에 맞는 기본 루프 및 setTimeout 대체 경로.
- [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame): 화면 주사율에 맞춰 호출되며 시간 기준으로 애니메이션을 갱신해야 한다.

setInterval/setTimeout은 화면 갱신과 동기화되지 않아 이 게임의 렌더 루프를 대체할 이점이 없다. 별도 requestAnimationFrame도 중복 업데이트 위험만 늘린다. Phaser의 기존 긴 delta 제한(50ms)과 창 복귀 첫 delta 무시 정책은 유지했다.

## 검증

- 자동 증가 1분/5분, 연속 가감속·해제·하한·상한 없음, 불규칙 delta, 20/30/60/144 FPS를 검사했다.
- 가감속 도중 충돌과 도착의 시간·속도·평균, 공중 가감속과 0.8초 점프 유지, 패드 모의 입력·터치 중복 입력·입력 초기화를 검사했다.
- 시야 확장 전후 기존 오브젝트·랜드마크의 위치/크기 불변, 원근 경계 연속성, 가감속 중 접근 방향 유지, 감속 시 기존 시야 유지 회귀 검사를 추가했다.
- 전체 172개 테스트, ESLint, TypeScript 검사, Next.js webpack 프로덕션 빌드 통과. 설치된 로컬 실행 파일로 package.json과 동일한 검증 명령을 실행했다.
- 내장 브라우저의 실제 Phaser 게임과 KeyboardInput을 임시 검증 페이지의 합성 keydown/keyup으로 구동했다. ↑ 4초: 14.1→46.0m/s, 해제 1초: 46.0m/s 유지, ↓ 5초: 현재 하한 14.2m/s. 일시정지 1초에도 14.2m/s 유지, 재개 정상.
- 해당 안전 코스 13초 표본: 1,561 프레임, requestAnimationFrame 간격 중앙값 8.3ms, 95백분위 9.3ms, 50ms 초과 0회. 브라우저/기기 전체의 성능 보증은 아니며 실물 게임패드와 모바일 하드웨어는 미검증이다. 임시 검증 페이지는 삭제했다.
